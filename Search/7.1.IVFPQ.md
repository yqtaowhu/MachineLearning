## 1. 概述

### 1.1 一句话定义

IVF+PQ = **倒排索引缩小搜索范围** + **乘积量化加速距离计算并压缩内存**，是大规模向量检索中最经典的组合方案。

### 1.2 为什么需要组合

| 单独使用 IVF | 单独使用 PQ |
|-------------|------------|
| 缩小了搜索范围（N → 几个聚类） | 加速了单次距离计算（$O(d)$ → $O(m)$） |
| 但倒排列表内仍需逐个算精确距离 | 但仍需遍历全部 N 个向量 |
| 内存仍为 $O(Nd)$（存原始向量） | 内存压缩到 $O(Nm)$ |

**组合后**：IVF 管"少算"，PQ 管"算得快 + 存得少"。

## 2. IVF 倒排索引详解

### 2.1 核心思想

类比搜索引擎的倒排索引：
- **文本搜索**：词项 → 包含该词的文档列表
- **向量搜索**：聚类中心（visual word） → 归属该中心的向量列表

### 2.2 构建流程（训练阶段）

```
输入：N 个 d 维向量
  ↓
Step 1: 对全量向量做 K-Means 聚类
  - 聚类数 = n_list（如 4000）
  - 迭代直到收敛（或达到最大迭代次数）
  - 得到 n_list 个聚类中心 c_1, c_2, ..., c_{n_list}
  ↓
Step 2: 将每个向量分配到最近的聚类中心
  - 对每个向量 x_i，找到 argmin_j ||x_i - c_j||
  - 形成 n_list 个倒排列表（posting list）
  ↓
Step 3: 存储
  - 聚类中心：n_list 个 d 维向量（用于查询时粗定位）
  - 倒排列表：每个列表存储其成员的向量 ID + 向量数据（原始或压缩）
```

**K-Means 训练细节**：
- 初始化：通常用 K-Means++ 或从训练数据中随机采样
- 迭代：每步将每个点分配到最近中心 → 重新计算中心 → 直到目标函数变化 < 阈值
- 目标函数（失真度）：$\sum_{i=1}^{N} \|x_i - c_{\text{assign}(i)}\|^2$

### 2.3 查询流程

```
输入：查询向量 q，参数 n_probe
  ↓
Step 1: 粗排（coarse quantization）
  - 计算 q 到所有 n_list 个聚类中心的距离
  - 选出最近的 n_probe 个聚类中心
  ↓
Step 2: 精排（fine search）
  - 在这 n_probe 个倒排列表中遍历
  - 对每个候选向量计算精确距离（IVFFlat）或近似距离（IVFPQ）
  - 用最大堆维护 Top-K
  ↓
输出：Top-K 最近邻
```

### 2.4 IVFFlat vs IVFPQ

| | IVFFlat | IVFPQ |
|--|---------|-------|
| 倒排列表中存储 | 原始 d 维向量 | PQ 编码（m 字节） |
| 距离计算 | 精确 $O(d)$ | 近似 $O(m)$ 查表 |
| 内存 | $O(Nd)$ | $O(Nm)$ |
| 召回率 | 较高 | 略低（量化损失） |
| 适用场景 | 内存充足，精度优先 | 大规模，内存受限 |

## 3. PQ 乘积量化详解

### 3.1 核心思想

把一个高维向量"切段编号"：
- 128 维向量 → 切成 16 段，每段 8 维
- 每段独立聚类到 256 个中心之一（8 bit）
- 整个向量用 16 个字节表示（vs 原始 512 字节，压缩 32 倍）

### 3.2 训练流程

```
输入：N 个 d 维向量，参数 m（子空间数）
  ↓
Step 1: 将 d 维空间等分为 m 个子空间
  - 子空间 j 对应第 j 段，维度 = d/m
  ↓
Step 2: 对每个子空间独立做 K-Means
  - 每个子空间聚类数 K = 256（即 8 bit，方便用 uint8 存储）
  - 得到 m 组聚类中心，每组 256 个 d/m 维向量
  ↓
输出：m × 256 个聚类中心（总参数量 = m × 256 × d/m = 256d）
```

### 3.3 编码流程

```
对每个向量 x = (x^(1), x^(2), ..., x^(m))：
  对每个子空间 j：
    找到最近的聚类中心：id_j = argmin_k ||x^(j) - c_{j,k}||
  编码结果：(id_1, id_2, ..., id_m)，共 m 字节
```

### 3.4 ADC 距离计算（核心）

**大白话**：查询时先建一张"距离对照表"，之后对每个向量只需查表 + 加法。

**Step 1 — 建距离表**（对查询向量 q，只做 1 次）：

$$
\text{dist\_table}[j][k] = d(q^{(j)}, c_{j,k}), \quad j \in [1,m], \; k \in [0, 255]
$$

计算量：$m \times 256$ 次 $\frac{d}{m}$ 维距离计算

**Step 2 — 对每个数据库向量查表求和**：

$$
\hat{d}(q, x) = \sum_{j=1}^{m} \text{dist\_table}[j][\text{id}_j]
$$

计算量：$m$ 次数组访问 + $m-1$ 次加法（极快！）

**Step 3 — 最大堆维护 Top-K**（同前文所述）

### 3.5 为什么 ADC 是"非对称"的

- **对称距离**：$d(q, x)$，两边都用原始向量
- **非对称距离**：$q$ 用原始向量，$x$ 用 PQ 编码
- 好处：$q$ 不压缩 → 精度损失只来自 $x$ 一侧，比双方都压缩精度更高

### 3.6 量化误差分析

PQ 的本质是用聚类中心"代表"原始向量，引入的误差为：

$$
\epsilon = \|x - \hat{x}\|^2 = \sum_{j=1}^{m} \|x^{(j)} - c_{j, \text{id}_j}\|^2
$$

误差取决于：
- 子空间维度 $\frac{d}{m}$：越大，每个子空间内聚类越难精确，误差越大
- 聚类数 $K$：越大，聚类中心越密，误差越小
- 数据分布：如果数据在某些子空间方差很大，量化误差也大

## 4. IVF+PQ 组合索引

### 4.1 完整构建流程

```
输入：N 个 d 维向量
  ↓
Phase 1: 训练 IVF 的聚类中心
  - K-Means 聚类 → n_list 个 coarse centroids
  ↓
Phase 2: 训练 PQ 的聚类中心
  - 将每个向量减去其最近的 coarse centroid（残差）
  - 对残差做 PQ 训练 → m × 256 个 fine centroids
  ↓
Phase 3: 编码存储
  - 每个向量存储：
    1. coarse_centroid_id（归属的倒排列表 ID）
    2. PQ 编码 (id_1, ..., id_m)（m 字节）
    3. 原始向量的 ID
```

> **关键细节**：PQ 是在**残差**上训练的，不是在原始向量上！
> 残差 = 原始向量 - 最近的 coarse centroid
> 这样 PQ 只需要编码"局部偏移"，量化误差更小。

### 4.2 完整查询流程

```
输入：查询向量 q，参数 n_probe
  ↓
Step 1: 粗定位（IVF 部分）
  - 计算 q 到所有 n_list 个 coarse centroids 的距离
  - 选出最近的 n_probe 个
  ↓
Step 2: 建 PQ 距离表
  - 将 q 减去每个选中的 coarse centroid → 得到 n_probe 个残差查询
  - 对每个残差查询，计算其 m 个子空间到 256 个 fine centroids 的距离
  - 生成 n_probe × m × 256 的距离表
  ↓
Step 3: 扫描 + 查表
  - 在 n_probe 个倒排列表中遍历
  - 对每个向量，用其 PQ 编码查表求和 → 近似距离
  - 最大堆维护 Top-K
  ↓
输出：Top-K 最近邻
```

### 4.3 内存分析

| 组件 | 内存 |
|------|------|
| coarse centroids | $n_{list} \times d \times 4$ 字节 |
| PQ 码本（fine centroids） | $m \times 256 \times \frac{d}{m} \times 4 = 256d \times 4$ 字节 |
| 每个向量的 PQ 编码 | $m$ 字节 |
| N 个向量的编码 | $N \times m$ 字节 |
| **总计** | $\approx N \times m$ 字节（主导项） |

**举例**：$N = 10^8, d = 128, m = 16$
- 原始向量：$10^8 \times 128 \times 4 = 48.8$ GB
- IVF+PQ：$10^8 \times 16 = 1.5$ GB（压缩 32 倍）

### 4.4 时间复杂度

| 阶段 | 复杂度 |
|------|--------|
| 训练 IVF | $O(N \cdot n_{list} \cdot d \cdot T)$（$T$ 为 K-Means 迭代次数） |
| 训练 PQ | $O(N \cdot m \cdot 256 \cdot \frac{d}{m} \cdot T)$ |
| 查询 Step 1 | $O(n_{list} \cdot d)$ |
| 查询 Step 2 | $O(n_{probe} \cdot m \cdot 256 \cdot \frac{d}{m})$ |
| 查询 Step 3 | $O(n_{probe} \cdot \frac{N}{n_{list}} \cdot m)$ |

## 5. IVF+PQ 的改进方案

### 5.1 OPQ（Optimized Product Quantization）

**问题**：PQ 假设各子空间独立，但实际数据可能存在子空间间的相关性。

**解决**：在 PQ 编码前，对向量施加一个正交旋转矩阵 $R$：

$$
x' = R \cdot x
$$

使得旋转后的向量在各子空间上的方差更均匀，量化误差更小。

**代价**：查询时需要额外做一次矩阵乘法 $q' = R \cdot q$，但 $R$ 是 $d \times d$ 的，计算量 $O(d^2)$，只做 1 次。

### 5.2 残差量化（Residual Quantization）

**问题**：PQ 的一次量化误差可能较大。

**解决**：对残差再做一次 PQ（二级量化）：

$$
x \xrightarrow{\text{1st PQ}} \hat{x}_1 \xrightarrow{\text{对残差 } x - \hat{x}_1 \text{ 再做 PQ}} \hat{x}_2
$$

最终近似 = $\hat{x}_1 + \hat{x}_2$，精度更高。

### 5.3 Polysemous Codes

**思想**：用更短的编码实现相同的精度。通过优化编码使得汉明距离能近似欧氏距离，从而可以用位运算加速。

### 5.4 SDC vs ADC

| | ADC（非对称） | SDC（对称） |
|--|-------------|------------|
| 查询端 | 原始向量 | 也做 PQ 编码 |
| 数据库端 | PQ 编码 | PQ 编码 |
| 距离计算 | 建表 + 查表 | 预计算 $256^2$ 距离表，直接查 |
| 精度 | 较高 | 略低 |
| 速度 | 中等 | 更快（纯整数查表） |

## 6. 参数调优实战

### 6.1 n_list 的选择

经验公式：$n_{list} = 4\sqrt{N}$

| N（向量数） | n_list（推荐） |
|------------|--------------|
| $10^4$ | 400 |
| $10^6$ | 4,000 |
| $10^8$ | 40,000 |
| $10^{10}$ | 400,000 |

**调参方法**：固定其他参数，画 Recall vs n_list 曲线，选拐点。

### 6.2 n_probe 的选择

$n_{probe}$ 直接控制 Recall-Latency 权衡：

```
n_probe = 1      → 最快，召回最低
n_probe = n_list → 退化为暴力搜索
```

**推荐起始值**：$n_{probe} = \lceil n_{list} \times 0.01 \rceil$（即搜索 1% 的聚类）

### 6.3 m（子空间数）的选择

| d（向量维度） | m（推荐） | d/m（子空间维度） | 压缩率 |
|-------------|----------|-----------------|--------|
| 64 | 8 | 8 | 2x |
| 128 | 16 | 8 | 2x |
| 256 | 32 | 8 | 2x |
| 128 | 32 | 4 | 4x（精度略降） |
| 128 | 64 | 2 | 8x（精度明显下降） |

**经验**：子空间维度 $d/m \geq 4$ 时精度较好；$d/m < 2$ 时误差明显增大。

### 6.4 FAISS 代码示例

```python
import faiss
import numpy as np

d = 128        # 向量维度
N = 1000000    # 向量数量
m = 16         # PQ 子空间数
nlist = 4000   # 聚类数

# 构建 IVF+PQ 索引
quantizer = faiss.IndexFlatL2(d)  # 粗量化的距离度量
index = faiss.IndexIVFPQ(quantizer, d, nlist, m, 8)  # 8 bits per sub-vector

# 训练（需要训练数据）
training_data = np.random.random((N, d)).astype('float32')
index.train(training_data)

# 添加向量
index.add(training_data)

# 查询
index.nprobe = 50  # 搜索 50 个聚类
query = np.random.random((10, d)).astype('float32')
D, I = index.search(query, k=100)  # 返回 Top-100
```

## 7. 具体例子

### 例子 1：IVF+PQ 完整流程

**问题**：4 个 4 维向量，IVF（$n_{list} = 2$）+ PQ（$m = 2$，$K = 2$），查询 $q = (3.5, 3.5, 3.5, 3.5)$，求 Top-2。

**数据库向量**：
- A = (1, 1, 1, 1)
- B = (2, 2, 2, 2)
- C = (5, 5, 5, 5)
- D = (6, 6, 6, 6)

**Step 1 — IVF 训练**：2-Means 聚类

| 聚类 | 中心 | 成员 |
|------|------|------|
| C1 | (1.5, 1.5, 1.5, 1.5) | A, B |
| C2 | (5.5, 5.5, 5.5, 5.5) | C, D |

**Step 2 — 计算残差**（每个向量减去其 coarse centroid）：

| 向量 | 归属 | 残差 |
|------|------|------|
| A | C1 | (-0.5, -0.5, -0.5, -0.5) |
| B | C1 | (0.5, 0.5, 0.5, 0.5) |
| C | C2 | (-0.5, -0.5, -0.5, -0.5) |
| D | C2 | (0.5, 0.5, 0.5, 0.5) |

**Step 3 — PQ 训练**（对残差做 PQ，$m=2, K=2$）：

子空间 1（前 2 维）的聚类中心：
| ID | 中心 |
|----|------|
| 0 | (-0.5, -0.5) |
| 1 | (0.5, 0.5) |

子空间 2（后 2 维）的聚类中心：
| ID | 中心 |
|----|------|
| 0 | (-0.5, -0.5) |
| 1 | (0.5, 0.5) |

**Step 4 — PQ 编码**：

| 向量 | 残差子向量1 | 编码 ID | 残差子向量2 | 编码 ID | PQ 编码 |
|------|-----------|---------|-----------|---------|---------|
| A | (-0.5, -0.5) | 0 | (-0.5, -0.5) | 0 | (0, 0) |
| B | (0.5, 0.5) | 1 | (0.5, 0.5) | 1 | (1, 1) |
| C | (-0.5, -0.5) | 0 | (-0.5, -0.5) | 0 | (0, 0) |
| D | (0.5, 0.5) | 1 | (0.5, 0.5) | 1 | (1, 1) |

**Step 5 — 查询**（$n_{probe} = 1$）：

粗定位：$q = (3.5, 3.5, 3.5, 3.5)$
- $d(q, C1) = \sqrt{4 \times 4} = 4.0$
- $d(q, C2) = \sqrt{4 \times 4} = 4.0$

距离相等，假设选 C2。

残差查询 = $q - C2 = (3.5-5.5, ...) = (-2, -2, -2, -2)$

建距离表：

| | 中心 0 (-0.5,-0.5) | 中心 1 (0.5,0.5) |
|--|-------------------|-----------------|
| 子空间1: (-2,-2) | $\sqrt{2.25+2.25} \approx 2.12$ | $\sqrt{6.25+6.25} \approx 3.54$ |
| 子空间2: (-2,-2) | $\sqrt{2.25+2.25} \approx 2.12$ | $\sqrt{6.25+6.25} \approx 3.54$ |

查表求和：
- C: 编码 (0,0) → $2.12 + 2.12 = 4.24$
- D: 编码 (1,1) → $3.54 + 3.54 = 7.08$

**结果**：Top-2 = {C(4.24), D(7.08)}

**结果解读**：注意这里的距离是**残差空间**中的近似距离，不是原始空间距离。真实距离 $d(q, C) = \sqrt{4 \times 2.25} = 3.0$，$d(q, D) = \sqrt{4 \times 6.25} = 5.0$。PQ 距离（4.24 vs 7.08）的排序与真实排序一致，但数值有偏差——这就是"近似"的含义。

### 例子 2：内存计算

**问题**：$N = 10^7$ 个 $d = 128$ 维向量，分别计算 IVFFlat 和 IVF+PQ（$m=16$）的内存占用。

**计算**：

| 组件 | IVFFlat | IVF+PQ |
|------|---------|--------|
| 聚类中心 | $4000 \times 128 \times 4 = 2$ MB | 同左 2 MB |
| 向量存储 | $10^7 \times 128 \times 4 = 4.88$ GB | $10^7 \times 16 = 152$ MB |
| **总计** | **≈ 4.88 GB** | **≈ 154 MB** |

压缩比：$4880 / 154 \approx 32$ 倍。

## 8. 常见面试问题

### Q1：IVF+PQ 中，PQ 是在原始向量上训练还是在残差上训练？为什么？

**答**：在**残差**上训练。残差 = 原始向量 - 最近的 coarse centroid。

原因：IVF 已经把向量按聚类中心分组，同一组内的向量彼此接近。对残差做 PQ 只需要编码"局部偏移"，量化误差远小于对全局向量做 PQ。如果不减残差，不同聚类的向量分布差异大，PQ 的聚类中心难以同时拟合所有区域。

### Q2：PQ 的 $m$ 选得越大越好吗？

**答**：不是。$m$ 越大：
- **优点**：子空间维度 $d/m$ 越小，每个子空间内聚类更精确，量化误差更小
- **缺点**：
  1. 压缩率降低（$m$ 字节 vs $4d$ 字节）
  2. 距离表更大（$m \times 256$），建表开销增加
  3. 当 $d/m < 2$ 时，子空间维度太低，聚类本身不稳定

经验：$d/m \geq 4$ 为宜。

### Q3：IVF+PQ 的召回率为什么不是 100%？损失来自哪里？

**答**：两处损失：
1. **IVF 损失**：$n_{probe} < n_{list}$ 时，某些真实最近邻可能落在未搜索的聚类中
2. **PQ 损失**：用聚类中心代替原始向量，引入量化误差，导致距离排序可能与真实不一致

两者叠加，使得最终 Top-K 可能遗漏真正的最近邻。

### Q4：如何在不增加太多内存的前提下提升 IVF+PQ 的召回率？

**答**：
1. 增大 $n_{probe}$（最直接，但增加延迟）
2. 增大 $m$（减小量化误差，但增加内存）
3. 使用 OPQ（正交优化，几乎不增加内存）
4. 对 Top-K 候选用原始向量做**重排序（rerank）**：离线存少量原始向量，在线对 PQ 粗筛的候选重算精确距离
5. 使用残差量化（RQ）替代 PQ

### Q5：IVF+PQ 和 HNSW 怎么选？

**答**：

| 场景 | 推荐 | 原因 |
|------|------|------|
| 内存受限（< 2GB） | IVF+PQ | 压缩率高 |
| 亿级数据 | IVF+PQ | 内存可控 |
| 高召回要求（>95%） | HNSW | 召回率更稳定 |
| 数据频繁更新 | HNSW | 支持增量插入 |
| 需要快速上线 | HNSW | 无需训练 |
