# 详细章节要点与面试问题设计细则

本文档为 SKILL.md 的补充参考，仅在需要深入细节时阅读。

## 各章节要点

### 1. 概述
- 第一句话必须是"一句话定义"，读者扫一眼就能知道这是什么
- 接着说明"为什么重要"：列出 3-4 点，包括数学性质优势、应用场景、业界使用频率
- 用 2-3 个生活化例子引入（如"广告点击率是多少？"），帮助建立直觉
- 禁止堆砌术语，术语首次出现时给出解释

### 2. 核心原理/公式
- 遵循"直觉先行，公式后置"：先解释这个公式在做什么，再给出公式
- 公式后必须逐符号解释含义
- 若主题有推导过程（如共轭先验、EM 算法），推导要完整展示中间步骤，不能跳步
- 推导结论用一句话总结（如"后验 = Beta(α+k, β+n-k)"）

### 3. 重要性质
- 每个性质独立小标题（如 3.1 期望、3.2 方差）
- 每条结构：公式 + 一句直觉解释 + 一句实际意义
- 性质之间有关联时明确写出（如"众数与期望的差别"）

### 4. 与其他概念的关系
- 用编号列表逐条说明，如"与均匀分布的关系"、"与 Gamma 分布的关系"
- 每条包含：关系公式（如有）+ 一句用途说明
- 可扩展方向：与该主题相关的上下位概念（如 Beta → Dirichlet）

### 5. 具体例子
- 至少 2 个例子，第 1 个选最简单的生活场景，第 2 个选工业界场景（CTR、推荐、NLP）
- 四段式：**问题**（一句话描述场景）→ **步骤**（设定先验/参数、观测数据）→ **计算**（代入公式，给出数字）→ **结果解读**（数字的含义、与频率派对比、先验影响等）
- 例子之间要有递进：第 2 个例子可以引出第 3 个（如从 CTR 估计引出汤普森采样）

### 6. 常见面试问题
- 编号 Q1-Q10，难度递增
- 前 2-3 题考概念理解（"是什么"），中间考公式与推导（"为什么/怎么推"），后 3-4 题考应用与延伸（"怎么做/如果…会怎样"）
- 每题答案 3-6 行，结构：直接答案 → 关键公式 → 直觉解释
- 覆盖该主题在推荐/搜索/NLP 中的高频考察点

## 面试问题设计细则

面试问题应覆盖以下四种类型，按难度排列：

| 类型 | 考察点 | 示例问题 | 答案要点 |
| --- | --- | --- | --- |
| 概念理解 | 定义、参数含义、直觉 | "什么是 Beta 分布？两个参数代表什么？" | 定义域 [0,1]、α/β 的伪计数解释 |
| 公式推导 | 期望、方差、后验推导 | "为什么 Beta 是二项分布的共轭先验？" | 写出先验 × 似然 ∝ 后验的过程 |
| 应用场景 | 工业界落地 | "如何用 Beta 分布做 CTR 平滑？" | 后验期望公式、小样本平滑动机 |
| 进阶延伸 | 边界条件、关联概念 | "Beta 与 Dirichlet 有什么关系？" | 一维多维推广、多项共轭 |

设计题目时的补充要求：
- 至少 1 道题考察"先验与数据如何折中"（如：先验 Beta(2,2) + 1 次成功，后验是什么？）
- 至少 1 道题考察"数据增多时行为变化"（贝叶斯一致性）
- 至少 1 道题给出频率派与贝叶斯派的对比视角
- 若有常见误区（如把众数当期望），专门设计一道题澄清

## 反面示例（避免这样写）

### 公式格式错误
```
❌ 用 \( \alpha \) 或 \[ E[X] \]
✅ 用 $ \alpha $ 或 $$ E[X] $$
```

### 例子没有数字
```
❌ "抛硬币后后验期望变大了"
✅ "后验 Beta(8,4)，期望 = 8/12 ≈ 0.667，相比先验期望 0.5 变大"
```

### 面试问题没有答案
```
❌ 只列问题不给参考答案
✅ 每题都给 3-6 行完整答案（直接答案 + 关键公式 + 直觉解释）
```

### 只有公式没有直觉
```
❌ 直接贴 PDF 公式结束
✅ 先解释"x 代表未知概率，α、β 代表成功/失败的证据量"
```
