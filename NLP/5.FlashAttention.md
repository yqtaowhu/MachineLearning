# FlashAttention 全系列：从原理到 v1/v2/v3/v4

> FlashAttention 系列是 Transformer 注意力机制加速的里程碑工作，由 Tri Dao 等人从 2022 年起持续迭代。核心思想：**让注意力算法"感知"硬件的内存层级，减少数据搬运，而非只盯着浮点运算量**。

---

## 1. 概述

**一句话定义**：FlashAttention 是一种 **IO 感知的精确注意力算法**，通过分块计算（Tiling）、在线 Softmax（Online Softmax）和重计算（Recomputation）技术，在不改变注意力数学结果的前提下，大幅减少 GPU 高带宽内存（HBM）的读写次数，从而实现 **2-4× 加速** 和 **O(N) 级别内存占用**（标准实现为 $O(N^2)$）。

**为什么重要**：
- 注意力机制是 Transformer 的**唯一通信瓶颈**——前馈网络可以并行，但注意力需要 token 之间两两交互
- 序列长度 $N$ 增大时，$N \times N$ 的注意力矩阵成为显存和带宽的双重杀手
- FlashAttention 已成为大模型训练和推理的**标配底层算子**，被 PyTorch、DeepSpeed、vLLM、HuggingFace 等框架广泛集成

---

## 2. 标准 Attention 的瓶颈

### 2.1 标准计算流程

$$S = QK^T \in \mathbb{R}^{N \times N}$$

$$P = \text{softmax}(S) \in \mathbb{R}^{N \times N}$$

$$O = PV \in \mathbb{R}^{N \times d}$$

其中 $N$ 为序列长度，$d$ 为 head 维度。

### 2.2 瓶颈分析

| 步骤 | 计算量（FLOPs） | HBM 读写量 |
|------|----------------|-----------|
| $S = QK^T$ | $O(N^2 d)$ | 读 $Q, K$，**写 $S$（$N^2$）** |
| $P = \text{softmax}(S)$ | $O(N^2)$ | **读 $S$（$N^2$）**，写 $P$（$N^2$） |
| $O = PV$ | $O(N^2 d)$ | **读 $P$（$N^2$）**，读 $V$，写 $O$ |

**核心问题**：中间矩阵 $S$ 和 $P$ 大小为 $N \times N$，需要反复在 HBM 和计算单元之间搬运。

> **大白话**：标准 Attention 就像做一道大菜，每次切完菜（算 $S$）要放回冰箱（HBM），炒菜时再拿出来（读 $S$），加完调料（softmax）又放回去，最后再拿出来装盘（乘 $V$）。冰箱和灶台之间来回跑，大部分时间都浪费在路上了。

### 2.3 IO 复杂度

标准实现的 HBM 访问量为 $O(N^2 d + N^2) = O(N^2 d)$，瓶颈在于**需要物化（materialize）完整的 $N \times N$ 中间矩阵**。

---

## 3. GPU 内存层级：HBM vs SRAM

理解 FlashAttention 之前，必须先理解 GPU 的两级存储：

| 存储层级 | 容量 | 带宽 | 延迟 | 类比 |
|---------|------|------|------|------|
| **HBM**（高带宽内存） | 大（A100: 40/80 GB） | ~1.5-2 TB/s | 高 | 冰箱（容量大但远） |
| **SRAM**（片上共享内存） | 小（A100: ~20 MB） | ~19 TB/s | 极低 | 灶台（容量小但近） |

**关键洞察**：SRAM 的带宽是 HBM 的 **~10 倍**，但容量只有 HBM 的 **~1/1000**。

> 注意力计算的瓶颈不在"算得慢"，而在"搬得慢"——**memory-bound**（访存受限），而非 compute-bound（计算受限）。

---

## 4. FlashAttention v1：IO 感知的精确注意力

> 论文：*FlashAttention: Fast and Memory-Efficient Exact Attention with IO-Awareness*（Tri Dao et al., 2022）

### 4.1 核心思想

**不存储完整的 $N \times N$ 注意力矩阵**，而是将 $Q, K, V$ 分块加载到 SRAM 中，在 SRAM 内完成局部计算，只把最终结果 $O$ 写回 HBM。

三大核心技术：

| 技术 | 作用 | 直觉 |
|------|------|------|
| **Tiling（分块）** | 将 $Q, K, V$ 切成小块，在 SRAM 中计算 | 每次只从冰箱拿一点食材到灶台 |
| **Online Softmax** | 流式计算 softmax，无需完整 $S$ 矩阵 | 边做菜边调味，不需要所有菜都上桌再调味 |
| **Recomputation** | 反向传播时重新计算 $S$，而非存储 | 不保留中间菜品，需要时重新做 |

### 4.2 Online Softmax 算法

标准 softmax 需要两遍扫描：第一遍找最大值 $m$，第二遍计算 $\sum e^{x_i - m}$。

**Online Softmax** 将两遍合并为一遍——维护 running max $m$ 和 running sum $l$，每读入一个新元素就增量更新：

$$m_{\text{new}} = \max(m_{\text{old}}, x_i)$$

$$l_{\text{new}} = l_{\text{old}} \cdot e^{m_{\text{old}} - m_{\text{new}}} + e^{x_i - m_{\text{new}}}$$

> 当新元素没有打破最大值记录时，$m_{\text{new}} = m_{\text{old}}$，缩放因子 $e^0 = 1$，直接累加；当新元素创新高时，旧的和被乘以 $e^{m_{\text{old}} - m_{\text{new}}} < 1$，自动"打折"修正。

### 4.3 FlashAttention 的分块注意力算法

将 Online Softmax 推广到整个注意力计算。设 $Q$ 分成 $T_r$ 块（每块 $B_r$ 行），$K, V$ 分成 $T_c$ 块（每块 $B_c$ 列）：

```
对每个 Q 的块 Q_i（加载到 SRAM）：
    初始化：m_i = -∞, l_i = 0, O_i = 0
    
    对每个 K, V 的块 K_j, V_j（加载到 SRAM）：
        1. 计算局部注意力分数：S_ij = Q_i · K_j^T / √d     （在 SRAM 中）
        2. 局部最大值：m_ij = rowmax(S_ij)
        3. 局部 softmax 分子：P_ij = exp(S_ij - m_ij)       （在 SRAM 中）
        4. 局部 softmax 分母：l_ij = rowsum(P_ij)
        
        5. 更新全局统计量（Online Softmax 核心）：
           m_new = max(m_i, m_ij)
           修正因子：α = exp(m_i - m_new)
           l_i = l_i · α + l_ij · exp(m_ij - m_new)
           O_i = O_i · α + P_ij · V_j · exp(m_ij - m_new)
           m_i = m_new
    
    最终输出：O_i = O_i / l_i
    将 O_i 写回 HBM
```

**关键**：全程不需要物化完整的 $N \times N$ 矩阵 $S$ 和 $P$，只需在 SRAM 中维护 $B_r \times B_c$ 的小块。

### 4.4 内存节省：重计算（Recomputation）

前向传播时不存储 $S$ 和 $P$（节省 $O(N^2)$ 显存），反向传播时**重新计算**这些中间值。

- 前向：只保存 $O$ 和 log-sum-exp 值 $L = \log l$（$O(N)$ 内存）
- 反向：用保存的 $Q, K, V, O, L$ 重新算出 $S, P$，再算梯度

> **代价**：多了一些 FLOPs（重计算），但由于省了大量 HBM 读写，**总时间反而更快**。

### 4.5 IO 复杂度分析

FlashAttention v1 的 HBM 访问量：

$$\text{IO} = O\left(\frac{N^2 d^2}{M}\right)$$

其中 $M$ 为 SRAM 大小。对比标准实现的 $O(N^2 d + N^2)$，当 $d \ll M$ 时（实际中 $d = 64$ 或 $128$，$M \approx 20$ MB），FlashAttention 的 IO 远小于标准实现。

**关键结论**：FlashAttention 的 IO 复杂度为 $O(Nd)$ 级别（固定 $d$ 时），而非 $O(N^2)$。

### 4.6 实验效果

- GPT-2 训练（序列长度 1K）：**提速 3×**，内存降低 **20×**
- 支持更长序列：可训练序列长度达 4K-16K（标准实现在 1K-2K 就 OOM）
- 精度完全一致：数学上等价于标准 Attention，非近似

## 5. FlashAttention v2：更好的并行与工作分配

> 论文：*FlashAttention-2: Faster Attention with Better Parallelism and Work Partitioning*（Tri Dao, 2023）

### 5.1 v1 的不足

v1 虽然解决了 IO 瓶颈，但在 GPU 利用率上还有提升空间：
- **非矩阵乘法操作（non-matmul FLOPs）占比高**：softmax 中的 exp、sum 等操作在 Tensor Core 外执行，拖慢了整体速度
- **并行粒度不够**：batch size 和 head 数较小时，GPU 的 SM（流多处理器）不能被充分占用

### 5.2 v2 的三大改进

#### 改进 1：减少 non-matmul FLOPs

- 调整分块策略，让每个 thread block 处理更多的 $Q$ 行（增大 $B_r$），减少 softmax 中 exp/sum 的启动开销
- 将 causal mask 的处理融入分块逻辑，避免额外的 mask 矩阵操作

#### 改进 2：更优的并行策略

- **在序列长度维度并行**：不仅沿 batch 和 head 维度并行，还沿序列长度维度分配不同的 thread block
- 对于 batch size = 1、head 数较少的推理场景，可以充分利用所有 SM

#### 改进 3：优化 warp 内工作分配

- 在 warp 内部，让每个线程处理连续的多个元素（而非交错分配），减少 shared memory 的 bank conflict
- 优化寄存器使用，减少 spill

### 5.3 性能对比

| 指标 | FlashAttention v1 | FlashAttention v2 |
|------|-------------------|-------------------|
| A100 前向峰值 | ~100 TFLOPs/s | **~230 TFLOPs/s** |
| A100 利用率 | ~25% | **50-73%** |
| 相对 v1 加速 | 基准 | **1.7-3.0×** |
| 支持特性 | MHA | MHA, **MQA, GQA** |

v2 还增加了对 **Multi-Query Attention（MQA）** 和 **Grouped-Query Attention（GQA）** 的原生支持，可显著减少推理时 KV Cache 的大小。

## 6. FlashAttention v3：异步执行与低精度

> 论文：*FlashAttention-3: Fast and Accurate Attention with Asynchrony and Low-precision*（2024，Tri Dao 联合 Meta、NVIDIA、Together AI 等）

### 6.1 研发背景

FlashAttention-2 在 H100 GPU 上仅实现了 **~35%** 的理论最大 FLOP 利用率。Hopper 架构引入了新的硬件特性，但 v2 未能充分利用：

- **WGMMA**（Warp Group Matrix Multiply-Accumulate）：异步张量核心指令
- **TMA**（Tensor Memory Accelerator）：异步数据搬运单元
- **FP8**：8 位浮点计算，吞吐量可达 FP16 的 2 倍

### 6.2 三大核心技术

#### 技术 1：Warp 专门化 + 生产者-消费者模型

将 thread block 内的 warp 分为两种角色：
- **生产者 warp**：使用 TMA 异步将数据从 HBM 加载到 shared memory
- **消费者 warp**：从 shared memory 读取数据，使用 Tensor Core 执行矩阵乘法

两类 warp **并行执行**，数据搬运和计算重叠，隐藏内存延迟。

#### 技术 2：GEMM 与 Softmax 异步交错

- 将分块矩阵乘法（GEMM）和 softmax 操作**流水线化**
- 采用**乒乓调度**：当 warp 组 A 执行 GEMM 时，warp 组 B 执行 softmax，交替进行
- 实现计算与数据移动的充分重叠

#### 技术 3：FP8 低精度 + 非相干处理（Incoherent Processing）

FP8 可以将 Tensor Core 吞吐量翻倍，但低精度会引入量化误差。FlashAttention-3 提出 **非相干处理**技术：
- 对 $Q, K$ 随机乘以 $\pm 1$ 的 Hadamard 变换符号，将异常值（outlier）分散
- 在 SRAM 内进行分块量化，减少量化误差
- 结果：FP8 精度下误差比标准 FP8 Attention **降低 2.6 倍**

### 6.3 性能对比

| 指标 | FlashAttention v2 | FlashAttention v3 |
|------|-------------------|-------------------|
| 目标硬件 | A100（Ampere） | **H100（Hopper）** |
| FP16 峰值 | ~230 TFLOPs/s | **740 TFLOPs/s** |
| 硬件利用率 | ~35%（H100 上） | **75%** |
| FP8 性能 | 不支持 | **~1.2 PFLOPs/s** |
| 相对 v2 加速 | 基准 | **1.5-2.0×** |

## 7. FlashAttention v4：Blackwell 架构优化

> FlashAttention-4 于 2025 年 Hot Chips 会议首次公布，2026 年 3 月正式发布。

### 7.1 研发背景

从 Hopper（H100）到 Blackwell（B200），硬件资源**非对称扩展**：
- BF16 Tensor Core 吞吐量：1 → 2.25 PFLOPs（**2.25×**）
- SFU（特殊函数单元）数量和共享内存带宽：**基本不变**

这导致 v3 的优化策略不再适用——**瓶颈发生了转移**：
- 前向传播：指数运算（exp）的 SFU 成为瓶颈
- 反向传播：shared memory 带宽成为瓶颈

### 7.2 核心技术

#### 技术 1：条件式 Softmax 重缩放

v1-v3 的 Online Softmax 每处理一个新块，最大值变化时都要对已累加结果做 rescaling。FA4 改为**只有当数值偏移大到威胁稳定性时才做缩放**，其余时候跳过——**跳过了约 90% 的 rescaling 操作**。

#### 技术 2：多项式近似指数计算

用软件模拟的多项式近似替代硬件 SFU 的指数函数，将 exp 计算分摊到 FMA（快速乘加）单元上，绕过 SFU 瓶颈。

#### 技术 3：利用张量内存（TMEM）

Blackwell 架构新增 TMEM（Tensor Memory），FA4 利用 TMEM 优化数据通路，配合新型软件流水线，提升前向和反向传播的整体效率。

### 7.3 性能对比

| 指标 | FlashAttention v3（H100） | FlashAttention v4（B200） |
|------|--------------------------|--------------------------|
| BF16 峰值 | 740 TFLOPs/s | **1605 TFLOPs/s** |
| 硬件利用率 | 75%（H100） | **71%**（B200） |
| vs cuDNN 9.13 | — | **快 1.1-1.3×** |
| vs Triton | — | **快 2.1-2.7×** |

## 9. 具体例子

### 例子 1：Online Softmax 分块计算过程

**问题**：给定注意力分数 $s = [2, 4, 1, 3]$，对应值 $V = [10, 20, 30, 40]$，分 2 块计算注意力输出。

**步骤**：

**块 1**：$s_1 = [2, 4]$，$V_1 = [10, 20]$

- $m_{\text{new}} = \max(-\infty, 2, 4) = 4$
- 修正旧值：$\alpha = e^{-\infty - 4} \approx 0$，$O_{\text{old}} \cdot 0 = 0$
- 新块贡献：$e^{2-4} \times 10 + e^{4-4} \times 20 = 0.135 \times 10 + 1 \times 20 = 21.35$
- $O_1 = 0 + 21.35 = 21.35$
- $l_1 = 0 + 0.135 + 1 = 1.135$
- $m = 4$

**块 2**：$s_2 = [1, 3]$，$V_2 = [30, 40]$

- $m_{\text{new}} = \max(4, 1, 3) = 4$（没变）
- 修正旧值：$\alpha = e^{4-4} = 1$，$O_{\text{old}} \cdot 1 = 21.35$
- 新块贡献：$e^{1-4} \times 30 + e^{3-4} \times 40 = 0.050 \times 30 + 0.368 \times 40 = 16.22$
- $O_2 = 21.35 + 16.22 = 37.57$
- $l_2 = 1.135 + 0.050 + 0.368 = 1.553$

**最终结果**：$O = O_2 / l_2 = 37.57 / 1.553 \approx 24.19$

**验证**（标准 softmax）：
- $m = 4$，$e^{s-m} = [0.135, 1, 0.050, 0.368]$
- $l = 1.553$
- $O = (0.135 \times 10 + 1 \times 20 + 0.050 \times 30 + 0.368 \times 40) / 1.553 = 24.19$ ✓

**结果解读**：Online Softmax 分块计算的结果与标准 softmax 完全一致，但全程不需要同时存储完整的 $s$ 向量——这就是 FlashAttention 能避免 $O(N^2)$ 内存的关键。

### 例子 2：IO 开销对比——序列长度 $N = 4096$，$d = 128$

**标准 Attention**：

- $S = QK^T$ 矩阵大小：$4096 \times 4096 \times 4 \text{ bytes} = 64 \text{ MB}$
- 需要写入 HBM：$S$（64 MB）+ $P$（64 MB）= **128 MB** 中间数据
- A100 HBM 带宽 ~2 TB/s，仅搬运这些中间数据就需要 ~64 μs（单次操作）

**FlashAttention**：

- SRAM 大小 ~20 MB，每次加载 $B_r \times d$ 的 $Q$ 块 + $B_c \times d$ 的 $K, V$ 块
- 取 $B_r = B_c = 128$：每块 $Q$ = $128 \times 128 \times 4 = 64$ KB，远小于 SRAM
- **不需要写回 $S$ 和 $P$**，只在 SRAM 内计算，最终输出 $O$（$4096 \times 128 \times 4 = 2$ MB）写回 HBM
- 中间 HBM 读写从 128 MB 降到几乎可以忽略

**结果解读**：当 $N = 4096$ 时，标准 Attention 仅注意力矩阵就需要 64 MB，而 A100 的 SRAM 总共只有 ~20 MB——根本放不下。FlashAttention 通过分块让数据始终在 SRAM 内流转，HBM 访问量降低了 **数十倍**。

## 10. 常见面试问题

### Q1：FlashAttention 的核心思想是什么？为什么能加速？

**答**：FlashAttention 的核心思想是 **IO 感知**（IO-aware）——设计算法时显式考虑 GPU 不同内存层级（HBM vs SRAM）之间的读写代价。

标准 Attention 的瓶颈不在计算（FLOPs），而在数据搬运（IO）。FlashAttention 通过三个技术加速：
1. **Tiling**：将 $Q, K, V$ 分块加载到 SRAM，在 SRAM 内完成局部计算
2. **Online Softmax**：流式计算 softmax，不需要完整的 $N \times N$ 矩阵
3. **Recomputation**：反向传播时重算中间值，节省 $O(N^2)$ 显存

**直觉**：不是算得更快，而是少搬数据。

### Q2：FlashAttention 是近似计算吗？会影响模型精度吗？

**答**：**不是近似，是精确计算**。FlashAttention 在数学上与标准 Attention 完全等价，只是计算顺序不同。

关键在于 Online Softmax 的增量更新保证了数值一致性——最终的 $O_i / l_i$ 与一次性计算全局 softmax 的结果在浮点精度范围内完全相同。

### Q3：什么是 Online Softmax？为什么标准 Softmax 不能直接分块？

**答**：标准 softmax 的归一化分母依赖**整行**所有元素：$\text{softmax}(x_i) = e^{x_i} / \sum_j e^{x_j}$。分块计算时，你无法预知后面块会不会出现更大的值，因此无法独立完成 softmax。

Online Softmax 通过维护 running max $m$ 和 running sum $l$，每处理一个新块就增量更新：

$$m_{\text{new}} = \max(m_{\text{old}}, m_{\text{block}})$$

$$l_{\text{new}} = l_{\text{old}} \cdot e^{m_{\text{old}} - m_{\text{new}}} + l_{\text{block}} \cdot e^{m_{\text{block}} - m_{\text{new}}}$$

当新块的最大值没有超过旧值时，修正因子为 1，直接累加；当出现新的最大值时，旧值自动"打折"修正。

### Q4：FlashAttention 为什么需要重计算（Recomputation）？代价是什么？

**答**：为了节省显存。标准 Attention 前向传播需要存储 $N \times N$ 的 $S$ 和 $P$ 矩阵用于反向传播。FlashAttention 前向时不存储这些中间矩阵（只保存 $O$ 和 log-sum-exp $L$），反向传播时**重新计算**。

**代价**：多了一次前向的计算量（约增加 20-25% 的 FLOPs），但由于省了大量 HBM 读写，**总训练时间反而减少 15-30%**。

### Q5：FlashAttention v2 相比 v1 做了哪些改进？

**答**：三个主要改进：
1. **减少 non-matmul FLOPs**：增大 $B_r$，减少 softmax 中 exp/sum 的启动开销
2. **序列维度并行**：在序列长度维度也分配 thread block，解决 batch size 小时 GPU SM 利用率低的问题
3. **Warp 内优化**：线程处理连续元素（而非交错），减少 shared memory bank conflict

效果：A100 上从 ~100 TFLOPs 提升到 ~230 TFLOPs，加速 1.7-3.0×。还新增了 MQA/GQA 支持。

### Q6：FlashAttention v3 为什么需要针对 Hopper 架构重新设计？

**答**：v2 在 H100 上只利用了 **35%** 的理论 FLOPs。Hopper 架构引入了 v2 未利用的新特性：
- **WGMMA**：异步 Tensor Core 指令
- **TMA**：异步数据搬运加速器
- **FP8**：8 位浮点计算

v3 通过 warp 专门化（生产者搬数据 + 消费者做计算）、GEMM 与 softmax 流水线交错、FP8 非相干处理三项技术，将利用率从 35% 提升到 **75%**。

### Q7：FlashAttention v3 的 FP8 非相干处理（Incoherent Processing）是什么？为什么需要？

**答**：FP8 精度低，直接量化 $Q, K$ 会引入显著误差，尤其是当矩阵中存在 outlier（异常大值）时。

非相干处理的做法：
1. 对 $Q, K$ 的每行随机乘以 $\pm 1$ 的 Hadamard 符号向量
2. 这相当于将 outlier "打散"到各个维度，使每维的值分布更均匀
3. 在 SRAM 内分块量化时，每块的值范围更小，量化误差更低

效果：FP8 FlashAttention-3 的误差比标准 FP8 Attention **降低 2.6 倍**。

### Q8：FlashAttention 对长序列的意义是什么？能否处理 100K 以上的序列？

**答**：FlashAttention 将注意力的内存复杂度从 $O(N^2)$ 降到 $O(N)$，使得长序列处理成为可能：
- 标准 Attention 在 $N = 16K$ 时，仅注意力矩阵就需要 ~1 GB 显存
- FlashAttention 在 $N = 16K$ 时，额外内存仅 ~几 MB

但注意：FlashAttention 的**计算复杂度**仍然是 $O(N^2)$（只是常数因子更小），所以极长序列（100K+）通常还需要结合 **稀疏注意力**（Sparse Attention）、**线性注意力**或 **Ring Attention**（分布式）等技术。

### Q9：FlashAttention 与 PagedAttention 的区别和联系？

**答**：两者解决不同的问题，可以互补：

| 维度 | FlashAttention | PagedAttention |
|------|---------------|----------------|
| **解决的问题** | 单次注意力计算的速度和显存 | 多请求并发时 KV Cache 的管理 |
| **核心思想** | IO 感知分块计算 | 分页管理 KV Cache（类似 OS 虚拟内存） |
| **优化目标** | 减少 HBM 读写 | 减少 KV Cache 的内存碎片和浪费 |
| **使用场景** | 训练 + 推理 | 主要用在推理（vLLM 等） |

实际部署中，vLLM 等推理框架同时使用 FlashAttention（加速计算）+ PagedAttention（管理 KV Cache），两者协同实现高吞吐推理。

### Q10：FlashAttention v4 相比 v3 的核心变化是什么？为什么不能直接复用 v3？

**答**：从 Hopper 到 Blackwell，硬件资源**非对称扩展**——Tensor Core 算力翻倍（2.25×），但 SFU 和 shared memory 带宽基本不变。v3 直接搬到 B200 上，**exp 运算的 SFU 成为前向瓶颈，shared memory 带宽成为反向瓶颈**。

v4 的三大针对性优化：
1. **条件式 softmax 重缩放**：跳过 90% 不必要的 rescaling
2. **多项式近似 exp**：用 FMA 单元替代 SFU 做指数运算，绕过 SFU 瓶颈
3. **利用 TMEM**：Blackwell 新增的张量内存，优化数据通路

效果：B200 上达到 1605 TFLOPs/s，比 cuDNN 快 1.1-1.3×。
