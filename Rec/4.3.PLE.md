# PLE：渐进分层提取多任务模型

## 1. 概述

&emsp;PLE（Progressive Layered Extraction，**渐进分层提取**）是腾讯 2020 年发表于 RecSys 的多任务学习模型，核心思想一句话：**把 MMoE 的"所有专家被所有任务共享"显式拆成"任务专属专家 + 共享专家"两组，并多层堆叠让表示逐层抽象，既保留跨任务迁移又避免任务竞争专家。**

&emsp;为什么重要？MMoE 虽然用门控缓解了任务冲突，但所有任务仍共享同一组专家——任务强冲突时，专家会被"拉扯"成折中状态，跷跷板现象并未完全消除。PLE 通过**显式分离专属容量与共享容量**，让每个任务有"自己的地盘"，同时保留共享专家提供跨任务迁移，多层堆叠进一步抽象表示。实验表明，任务冲突强时 PLE 显著优于 MMoE，成为工业界多任务建模的进阶选择。

## 2. 背景：MMoE 的局限与跷跷板残留

&emsp;先回顾 MMoE 的结构：$n$ 个专家被所有任务共享，每个任务一个门控对专家输出加权求和。它确实缓解了任务冲突（见 MMoE 文档例 2 的梯度分流），但有一个隐含问题：

&emsp;**所有任务竞争同一批专家**。假设任务 A（CTR）和任务 B（CVR）冲突强烈：
- 训练早期，专家 1 偏向任务 A 的方向，专家 2 偏向任务 B 的方向；
- 但随着训练推进，任务 A 的梯度会"推"专家 2 向任务 A 方向移动，任务 B 的梯度也会"推"专家 1 向任务 B 方向移动——因为两个任务都用到所有专家；
- 最终专家被拉扯成"折中"状态，既不完全服务任务 A，也不完全服务任务 B，跷跷板现象残留。

&emsp;直觉类比：MMoE 像两个租客共用一套公寓（所有专家），虽然可以约定"客厅归我用、卧室归你用"（门控加权），但厨房、卫生间还是共享的，冲突时只能妥协。PLE 的做法是**给每个租客一个独立房间（专属专家），客厅卫生间保留共享（共享专家）**——冲突时各回各屋，共享区域只用于"互通有无"。

&emsp;MMoE 的另一个局限：**单层结构**。所有专家只有一层，表示能力有限。多层堆叠（像 ResNet 或 Transformer 的多层）可以逐层抽象，但 MMoE 没有这个机制。

&emsp;PLE 同时解决这两个问题：① 显式分离专属/共享专家；② 多层渐进提取。

## 3. 核心原理：专属专家 + 共享专家 + 渐进提取

&emsp;PLE 的核心分两部分：**单层 CGC（Customized Gate Control）** 和**多层 PLE（CGC 堆叠）**。

### 3.1 CGC：单层定制门控

&emsp;CGC 是 PLE 的基本单元。设共 $K$ 个任务，每个任务 $k$ 有：

- **专属专家**：$n_k$ 个，记为 $e_1^k, \dots, e_{n_k}^k$，只服务任务 $k$；
- **共享专家**：$n_s$ 个，记为 $e_1^s, \dots, e_{n_s}^s$，服务所有任务；
- **门控**：$g^k(x) = \text{softmax}(W_{gk}\, x)$，输出 $n_k + n_s$ 维权重（专属 + 共享），和为 1。

&emsp;任务 $k$ 的塔输入是专属专家 + 共享专家的加权组合：

$$f^k(x) = \sum_{i=1}^{n_k} g_i^k(x) \, e_i^k(x) + \sum_{j=1}^{n_s} g_{n_k+j}^k(x) \, e_j^s(x)$$

&emsp;把核心公式框起来：

$$\boxed{\,f^k(x) = \underbrace{\sum_{i=1}^{n_k} g_i^k(x) \, e_i^k(x)}_{\text{专属专家贡献}} + \underbrace{\sum_{j=1}^{n_s} g_{n_k+j}^k(x) \, e_j^s(x)}_{\text{共享专家贡献}}\,}$$

&emsp;直觉要点：

- **专属专家**：只被任务 $k$ 的门控使用，梯度只来自任务 $k$，不会被其他任务拉扯——保留任务特异性；
- **共享专家**：被所有任务的门控使用，梯度来自所有任务——提供跨任务迁移（类似 MMoE 的专家）；
- **门控**：任务 $k$ 的门控对专属 + 共享专家做加权，决定"这个样本、这个任务，应该用多少专属容量 vs 共享容量"。

### 3.2 多层 PLE：CGC 堆叠

&emsp;单层 CGC 的表示能力有限。PLE 把多个 CGC 堆叠成多层，每层的输出作为下一层的输入：

- **第 1 层**：输入是原始特征 $x$，每个任务 $k$ 有一个 CGC 单元，输出 $f_1^k(x)$；
- **第 2 层**：输入是第 1 层的输出 $\{f_1^1(x), \dots, f_1^K(x)\}$，每个任务 $k$ 有一个 CGC 单元，输出 $f_2^k(x)$；
- ……
- **第 $L$ 层**：输出 $f_L^k(x)$ 接任务塔 $h_k$，得到最终输出 $\hat{y}_k = h_k(f_L^k(x))$。

&emsp;多层堆叠的意义：低层 CGC 学习"基础特征组合"（如用户-物品交互），高层 CGC 学习"抽象任务表示"（如 CTR 任务的高层表示可能组合低层的点击相关特征）。逐层抽象让模型表达能力更强，类似 ResNet 的多层结构。

## 4. 模型结构：CGC 与多层 PLE

&emsp;以 2 任务（CTR、CVR）为例，单层 CGC 的结构：

1. **输入层**：特征 $x \in \mathbb{R}^d$；
2. **专家层**：
   - 任务 A（CTR）专属专家：$n_A$ 个 MLP，输入 $x$，输出 $d'$ 维；
   - 任务 B（CVR）专属专家：$n_B$ 个 MLP，输入 $x$，输出 $d'$ 维；
   - 共享专家：$n_s$ 个 MLP，输入 $x$，输出 $d'$ 维；
3. **门控层**：
   - 任务 A 门控：$g^A(x) = \text{softmax}(W_{gA}\, x)$，输出 $n_A + n_s$ 维权重；
   - 任务 B 门控：$g^B(x) = \text{softmax}(W_{gB}\, x)$，输出 $n_B + n_s$ 维权重；
4. **加权组合**：
   - 任务 A 塔输入：$f^A = \sum_{i=1}^{n_A} g_i^A \, e_i^A + \sum_{j=1}^{n_s} g_{n_A+j}^A \, e_j^s$；
   - 任务 B 塔输入：$f^B = \sum_{i=1}^{n_B} g_i^B \, e_i^B + \sum_{j=1}^{n_s} g_{n_B+j}^B \, e_j^s$；
5. **任务塔层**：
   - CTR 塔：$h_A(f^A)$ → pCTR；
   - CVR 塔：$h_B(f^B)$ → pCVR。

&emsp;多层 PLE：把上述 CGC 堆叠 $L$ 层，第 $l$ 层的输入是第 $l-1$ 层各任务的输出（第 1 层输入是 $x$）。

&emsp;损失函数与 MMoE 相同：

$$L = \sum_{k=1}^{K} w_k \, L_k$$

&emsp;其中 $w_k$ 是任务权重，$L_k$ 是任务 $k$ 的损失。梯度分配：任务 $k$ 的专属专家只接收任务 $k$ 的梯度，共享专家接收所有任务的梯度（按门控加权）。

## 5. 为什么 PLE 有效

1. **显式分离专属/共享容量**：专属专家只服务一个任务，梯度不冲突，保留任务特异性；共享专家服务所有任务，提供跨任务迁移。MMoE 中"所有专家被所有任务共享"的隐式分工变成显式设计，避免专家竞争。
2. **多层渐进提取**：低层学习基础特征组合，高层学习抽象任务表示，逐层抽象增强表达能力。实验表明多层 PLE 优于单层 CGC。
3. **缓解跷跷板**：专属专家不被其他任务拉扯，任务 A 提升时不会拖累任务 B；共享专家提供迁移但权重可控（门控决定用多少共享容量）。
4. **灵活容量分配**：可以调整专属专家数量 $n_k$ 和共享专家数量 $n_s$，根据任务相关性调整。任务相关性弱时增加专属专家；相关性强时增加共享专家。
5. **退化有界**：若 $n_s = 0$（无共享专家），PLE 退化为 K 个独立模型；若 $n_k = 0$（无专属专家），PLE 退化为 MMoE（单层）。这说明 PLE 是 MMoE 的严格推广。

## 6. 与其他概念的关系

| 对比对象 | 差异点 |
|---|---|
| MMoE | MMoE 所有专家被所有任务共享，专家竞争导致跷跷板残留；PLE 显式分离专属/共享专家，缓解竞争。PLE 是 MMoE 的推广（$n_k=0$ 时退化为 MMoE） |
| Shared-Bottom | 硬共享，所有任务共用一套底层参数；PLE 用专属/共享专家 + 门控实现"软共享"，更灵活 |
| 单任务模型 × K | 无共享收益；PLE 保留共享专家提供跨任务迁移 |
| ESMM | ESMM 解决"样本空间偏差 + 数据稀疏"，输出层有乘法结构先验；PLE 解决"任务冲突"，作用在表示层。两者互补，可结合：PLE 作共享层 + ESMM 乘法分解输出 |
| CGC | CGC 是 PLE 的单层版本；PLE 是多层 CGC 堆叠，表达能力更强 |

## 7. 具体例子

### 例 1：单层 CGC 前向计算——专属 + 共享专家的加权组合

**问题**：设 2 任务（A = CTR，B = CVR），任务 A 有 2 个专属专家 $e_1^A, e_2^A$，任务 B 有 2 个专属专家 $e_1^B, e_2^B$，1 个共享专家 $e_1^s$。给定样本 $x$，专家输出（2 维）：
- $e_1^A(x) = (1, 2)$，$e_2^A(x) = (3, 1)$
- $e_1^B(x) = (2, 3)$，$e_2^B(x) = (1, 4)$
- $e_1^s(x) = (2, 2)$

门控 logits 经 softmax 后：
- 任务 A 门控 $g^A = (0.4, 0.3, 0.3)$（对应 $e_1^A, e_2^A, e_1^s$）
- 任务 B 门控 $g^B = (0.2, 0.5, 0.3)$（对应 $e_1^B, e_2^B, e_1^s$）

分别计算任务 A、B 的塔输入 $f^A, f^B$。

**步骤**：套用 CGC 公式 $f^k = \sum_{i} g_i^k \, e_i^k + \sum_{j} g_{n_k+j}^k \, e_j^s$。

**计算**：

- 任务 A：$f^A = 0.4 \times (1, 2) + 0.3 \times (3, 1) + 0.3 \times (2, 2) = (0.4 + 0.9 + 0.6,\; 0.8 + 0.3 + 0.6) = (1.9, 1.7)$
- 任务 B：$f^B = 0.2 \times (2, 3) + 0.5 \times (1, 4) + 0.3 \times (2, 2) = (0.4 + 0.5 + 0.6,\; 0.6 + 2.0 + 0.6) = (1.5, 3.2)$

**结果解读**：任务 A 的塔输入 $f^A = (1.9, 1.7)$ 主要由专属专家 $e_1^A, e_2^A$ 贡献（权重 0.4 + 0.3 = 0.7），共享专家贡献 0.3；任务 B 的塔输入 $f^B = (1.5, 3.2)$ 主要由专属专家 $e_2^B$ 贡献（权重 0.5），共享专家贡献 0.3。两个任务的专属专家"各司其职"，共享专家提供"公共信息"——这就是 PLE 的显式分工。

### 例 2：多层 PLE 的渐进提取——高层组合低层表示

**问题**：设 2 层 PLE，每层是 CGC。第 1 层输入是原始特征 $x$，输出 $f_1^A, f_1^B$；第 2 层输入是第 1 层的输出 $\{f_1^A, f_1^B\}$，输出 $f_2^A, f_2^B$。假设第 1 层已学到"基础特征"（如用户-物品交互），第 2 层如何组合？

**步骤**：第 2 层的专家输入是第 1 层的输出（而非原始特征 $x$），门控也输入第 1 层输出。

**计算**（示意）：

- 第 1 层：$f_1^A = (1.9, 1.7)$（CTR 基础表示），$f_1^B = (1.5, 3.2)$（CVR 基础表示）；
- 第 2 层专家输入：
  - CTR 专属专家：$e_1^A(f_1^A) = (2.5, 1.0)$，$e_2^A(f_1^A) = (1.2, 2.3)$
  - CVR 专属专家：$e_1^B(f_1^B) = (1.8, 2.9)$，$e_2^B(f_1^B) = (2.1, 1.5)$
  - 共享专家：$e_1^s(f_1^A, f_1^B) = (2.0, 2.0)$（输入拼接）
- 第 2 层门控（示意权重）：
  - 任务 A 门控 $g_2^A = (0.5, 0.3, 0.2)$（专属 + 共享）
  - 任务 B 门控 $g_2^B = (0.4, 0.4, 0.2)$
- 第 2 层输出：
  - $f_2^A = 0.5 \times (2.5, 1.0) + 0.3 \times (1.2, 2.3) + 0.2 \times (2.0, 2.0) = (1.25 + 0.36 + 0.4,\; 0.5 + 0.69 + 0.4) = (2.01, 1.59)$
  - $f_2^B = 0.4 \times (1.8, 2.9) + 0.4 \times (2.1, 1.5) + 0.2 \times (2.0, 2.0) = (0.72 + 0.84 + 0.4,\; 1.16 + 0.6 + 0.4) = (1.96, 2.16)$

**结果解读**：第 2 层在第 1 层学到的"基础表示"上进一步抽象——CTR 任务的高层表示 $f_2^A$ 组合了低层的 CTR 专属特征和共享特征，CVR 任务同理。多层堆叠让模型逐层学习从"基础交互"到"任务特异性抽象"的表示，表达能力更强。

## 8. 示例代码（PyTorch）

&emsp;单层 CGC 与多层 PLE 的核心实现（2 任务，可直接拼接到自己的数据管线）：

```python
class CGC(nn.Module):
    """单层 CGC：任务专属专家 + 共享专家 + 门控加权"""
    def __init__(self, n_in=16, n_experts_per_task=2, n_shared_experts=1, expert_dim=8):
        super().__init__()
        self.n_tasks = 2
        self.n_experts_per_task = n_experts_per_task
        self.n_shared_experts = n_shared_experts
        
        # 任务专属专家：每个任务 n_experts_per_task 个
        self.task_experts = nn.ModuleList([
            nn.ModuleList([
                nn.Sequential(nn.Linear(n_in, expert_dim), nn.ReLU())  # (n, 16) -> (n, 8)
                for _ in range(n_experts_per_task)])
            for _ in range(self.n_tasks)])
        
        # 共享专家：n_shared_experts 个
        self.shared_experts = nn.ModuleList([
            nn.Sequential(nn.Linear(n_in, expert_dim), nn.ReLU())      # (n, 16) -> (n, 8)
            for _ in range(n_shared_experts)])
        
        # 门控：每个任务一个，输入 n_in，输出 n_experts_per_task + n_shared_experts
        self.gates = nn.ModuleList([
            nn.Linear(n_in, n_experts_per_task + n_shared_experts)     # (n, 16) -> (n, 3)
            for _ in range(self.n_tasks)])

    def forward(self, x):
        # 任务专属专家输出：task_outs[k][i] = (n, expert_dim)
        task_outs = [[expert(x) for expert in experts] for experts in self.task_experts]
        
        # 共享专家输出：shared_outs[j] = (n, expert_dim)
        shared_outs = [expert(x) for expert in self.shared_experts]
        
        outs = []
        for k in range(self.n_tasks):
            g = torch.softmax(self.gates[k](x), dim=-1)                # (n, 3) 门控权重
            # 专属专家加权
            task_weighted = sum(g[:, i:i+1] * task_outs[k][i] 
                               for i in range(self.n_experts_per_task))
            # 共享专家加权
            shared_weighted = sum(g[:, self.n_experts_per_task + j:self.n_experts_per_task + j + 1] 
                                 * shared_outs[j] 
                                 for j in range(self.n_shared_experts))
            outs.append(task_weighted + shared_weighted)                 # (n, expert_dim)
        return outs


class PLE(nn.Module):
    """多层 PLE：CGC 堆叠"""
    def __init__(self, n_in=16, n_layers=2, n_experts_per_task=2, n_shared_experts=1, 
                 expert_dim=8, hidden=64):
        super().__init__()
        self.n_layers = n_layers
        
        # 多层 CGC
        self.cgc_layers = nn.ModuleList([
            CGC(n_in if l == 0 else expert_dim, n_experts_per_task, 
                n_shared_experts, expert_dim)
            for l in range(n_layers)])
        
        # 任务塔
        self.towers = nn.ModuleList([
            nn.Sequential(nn.Linear(expert_dim, hidden), nn.ReLU(),
                          nn.Linear(hidden, 1))                          # (n, 8) -> (n, 1)
            for _ in range(2)])

    def forward(self, x):
        outs = [x, x]  # 初始输入（两个任务都用 x）
        for cgc in self.cgc_layers:
            outs = cgc(outs[0] if len(outs) == 1 else torch.cat(outs, dim=-1))
        
        # 任务塔
        return [tower(outs[k]).squeeze(-1) for k, tower in enumerate(self.towers)]

# 训练：L = w_A * L_A + w_B * L_B
logitA, logitB = model(x)
loss = bce(logitA, yA) + bce(logitB, yB)
loss.backward()
```

&emsp;要点：① CGC 中任务专属专家只被对应任务的门控使用，共享专家被所有任务使用；② 多层 PLE 中每层 CGC 的输入是上一层的输出（第 1 层输入是 $x$）；③ 门控权重和为 1（softmax），专属 + 共享专家贡献加权求和。

## 9. 常见面试问题

**Q1：PLE 是什么？它解决 MMoE 的什么问题？**

答：PLE（Progressive Layered Extraction，渐进分层提取）是腾讯 2020 年提出的多任务学习模型。它解决 MMoE 的两个局限：① MMoE 所有专家被所有任务共享，任务强冲突时专家被"拉扯"成折中状态，跷跷板现象残留；② MMoE 单层结构表示能力有限。PLE 通过显式分离"任务专属专家 + 共享专家"并多层堆叠，既保留跨任务迁移又避免任务竞争专家。

**Q2：写出 CGC（PLE 单层版本）的前向公式。**

答：设任务 $k$ 有 $n_k$ 个专属专家 $e_1^k, \dots, e_{n_k}^k$ 和 $n_s$ 个共享专家 $e_1^s, \dots, e_{n_s}^s$。任务 $k$ 的门控 $g^k(x) = \text{softmax}(W_{gk}\, x)$，输出 $n_k + n_s$ 维权重。任务 $k$ 的塔输入：

$$f^k(x) = \sum_{i=1}^{n_k} g_i^k(x) \, e_i^k(x) + \sum_{j=1}^{n_s} g_{n_k+j}^k(x) \, e_j^s(x)$$

即专属专家 + 共享专家的加权组合，门控决定用多少专属容量 vs 共享容量。

**Q3：PLE 如何缓解跷跷板现象？**

答：专属专家只服务一个任务，梯度只来自该任务，不会被其他任务拉扯——保留任务特异性；共享专家服务所有任务，提供跨任务迁移但权重可控（门控决定用多少）。任务 A 提升时，专属专家只接收任务 A 的梯度，不会拖累任务 B；共享专家被所有任务使用，但门控可以限制共享容量占比，避免过度迁移。

**Q4：PLE 与 MMoE 的核心区别是什么？**

答：MMoE 所有专家被所有任务共享，专家竞争导致跷跷板残留；PLE 显式分离专属/共享专家，专属专家只服务一个任务，共享专家服务所有任务。PLE 是 MMoE 的推广（$n_k=0$ 时退化为 MMoE）。实验表明任务冲突强时 PLE 显著优于 MMoE。

**Q5：为什么需要"共享专家"？直接用 K 个独立模型不行吗？**

答：K 个独立模型无共享收益，数据稀疏任务（如 CVR）无法借力充足任务（CTR）的表示。共享专家提供跨任务迁移：任务相关性强时，共享专家学到的表示可以被多个任务复用，缓解稀疏。PLE 的设计是"专属专家保留特异性 + 共享专家提供迁移"的折中。

**Q6：多层 PLE 的意义是什么？单层 CGC 不够吗？**

答：单层 CGC 的表示能力有限。多层堆叠让模型逐层抽象：低层学习"基础特征组合"（如用户-物品交互），高层学习"抽象任务表示"（如 CTR 任务的高层表示组合低层的点击相关特征）。实验表明多层 PLE 优于单层 CGC，类似 ResNet 的多层结构增强表达能力。

**Q7：PLE 有哪些缺点？**

答：① 参数量增加：专属专家 + 共享专家 + 多层 CGC，参数量远大于 MMoE，训练和推理开销大；② 超参数多：需要调整专属专家数 $n_k$、共享专家数 $n_s$、层数 $L$，调参成本高；③ 任务相关性弱时专属专家可能过拟合（数据不足），相关性强时共享专家可能引入噪声。

**Q8：PLE 与 ESMM 怎么结合？**

答：两者解决不同问题：PLE 在表示层解决任务冲突（专属/共享专家），ESMM 在输出层利用"转化依赖点击"的漏斗先验（$pCTCVR = pCTR \times pCVR$），解决 CVR 的样本选择偏差与数据稀疏。可以结合：PLE 作共享表示层（替代 MMoE）+ 双塔 + 乘法分解输出。工业界常见做法。

**Q9：PLE 中专属专家和共享专家的数量怎么选？**

答：根据任务相关性调整：任务相关性弱时增加专属专家（保留特异性），减少共享专家（避免噪声迁移）；任务相关性强时增加共享专家（促进迁移），减少专属专家。实践中可以设 $n_k = 2 \sim 4$，$n_s = 1 \sim 2$，通过 AUC 增益和门控权重分布诊断调整。若某任务门控中共享专家权重接近 0，说明该任务不需要共享容量；若接近 1，说明该任务高度依赖共享容量。

**Q10：PLE 实际落地中有哪些工程挑战？**

答：① 参数量大：专属专家 + 共享专家 + 多层 CGC，模型体积大，线上推理延迟增加，需要模型压缩（剪枝、量化）或知识蒸馏；② 训练不稳定：多层 CGC 梯度传播路径长，可能梯度消失/爆炸，需要残差连接或梯度裁剪；③ 门控退化：训练中门控可能退化为 one-hot（只用一个专家）或均匀（所有专家等权），需要加熵正则或温度调节；④ 超参数敏感：专属/共享专家比例、层数、学习率等需要精细调优，成本高。
