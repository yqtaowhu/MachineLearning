## 1.概述

**一句话定义**：on-policy（在轨策略）指**只用"当前正在优化的策略自己产生的数据"来更新自己**；off-policy（离轨策略）指**可以用其他策略（旧版本策略、专家策略、经验池里的历史数据）产生的数据来学习**。一句话判断法：问"这段训练数据是谁产生的？"——是当前策略自己产生的就是 on-policy，别人（包括过去的自己）产生的就是 off-policy。

**为什么重要**：
- 它是强化学习算法分类的第一把钥匙：Q-learning、DQN、SAC 是 off-policy，REINFORCE、A2C、PPO、GRPO 是 on-policy；
- 它决定了**样本效率和稳定性的取舍**：off-policy 能反复复用旧数据（样本效率高），但要做分布修正、容易不稳定；on-policy 数据用完即弃（成本高），但分布一致、训练稳定；
- 在大模型时代它是理解后训练算法的坐标轴：SFT 学的是人类的示范（off-policy），PPO/GRPO 学的是自己输出的后果（on-policy），DPO 优化的是静态偏好对（offline）。理解了这对概念，SFT/RLHF/DPO/RLVR 四代后训练方法的演进逻辑就串起来了。

先用两个生活化例子建立直觉：

- **学开车**：on-policy 像"自己上路开、自己承担后果来改进驾驶习惯"；off-policy 像"看老司机的行车记录仪录像学车"——录像不是自己产生的，但确实能学到东西，只是要小心"别人开车的路况和我现在遇到的不一样"。
- **学做菜**：on-policy 是"自己炒一盘、尝一口、改进配方，然后把这盘倒掉重来"；off-policy 是"把过去 10 万次炒菜记录存在本子里，随时翻出来复盘，甚至研究米其林大厨的操作"。

## 2.核心原理

### 2.1 前置概念：行为策略与目标策略

严格定义这对概念需要两个术语（大白话见 [3.1.PPO算法详解](3.1.PPO算法详解.md) 的 2.1 节）：

| 符号 | 名字 | 大白话 |
|------|------|--------|
| $\beta(a\|s)$ | 行为策略 Behavior Policy | **实际去和环境交互、采集数据**的那个策略（"谁在玩"） |
| $\pi_\theta(a\|s)$ | 目标策略 Target Policy | **正在被优化、最终要部署**的那个策略（"要学成什么样"） |

于是有严格定义：

- **on-policy**：$\beta = \pi_\theta$，行为策略就是目标策略本身。数据是"我要学成的那个自己"产生的，分布天然一致。
- **off-policy**：$\beta \neq \pi_\theta$，行为策略和目标策略是两个（可以差得很远）。比如 DQN 里用 $\varepsilon$-greedy 探索着采数据，但学的目标是完全贪心的最优策略。

注意判断的口径：很多文献把"旧版本策略产生的数据"也算 off-policy——因为策略更新一步后，$\pi_{\text{old}} \neq \pi_{\text{new}}$，旧数据对当前策略来说就是"别人产生的"。

### 2.2 Off-policy 的数学工具：重要性采样

off-policy 的核心难题：我的梯度公式期望是在 $\tau \sim \pi_\theta$ 下定义的，但数据却来自 $\beta$。**怎么用"别人的分布"下的平均，去估计"我的分布"下的平均？**

答案是重要性采样（importance sampling）：给每个样本乘一个概率比作为权重，$\pi_\theta$ 下不太可能出现的数据降权，常见的数据加权，从而把 $\beta$ 下的期望"搬运"到 $\pi_\theta$ 下：

$$\mathbb{E}_{\tau \sim \pi_\theta}[f(\tau)] = \mathbb{E}_{\tau \sim \beta}\left[\frac{P_{\pi_\theta}(\tau)}{P_\beta(\tau)} f(\tau)\right]$$

- $P_{\pi_\theta}(\tau)$：轨迹 $\tau$ 在目标策略下出现的概率
- $P_\beta(\tau)$：同一轨迹在行为策略下出现的概率
- 比值 $\frac{P_{\pi_\theta}(\tau)}{P_\beta(\tau)}$ 就是重要性权重，单步动作的形式为 $\frac{\pi_\theta(a\|s)}{\beta(a\|s)}$

对策略梯度套用这个修正，就得到 off-policy 策略梯度的基本形式：

$$\nabla_\theta J(\theta) = \mathbb{E}_{a \sim \beta}\left[\frac{\pi_\theta(a\|s)}{\beta(a\|s)} \nabla_\theta \log \pi_\theta(a\|s)\, A(s,a)\right]$$

直觉：优势 $A$ 说明了"这个动作好不好"，概率比说明了"这个动作在我的策略下比在采数据的策略下出现得多还是少"——把别人的经验按相关度折算成自己的经验。

**代价**：轨迹级的概率比是一整条轨迹上每一步比值的连乘：

$$\frac{P_{\pi_\theta}(\tau)}{P_\beta(\tau)} = \prod_{t=0}^{T} \frac{\pi_\theta(a_t\|s_t)}{\beta(a_t\|s_t)}$$

两个策略稍有差异，连乘几百上千步后这个权重要么爆炸要么趋零，**方差随轨迹长度指数级增长**。这是 off-policy 修正的阿喀琉斯之踵（见 3.2 节）。

### 2.3 On-policy 的取舍：数据即弃

on-policy 走的是另一条路：**不修正分布，直接让数据分布 = 策略分布**。

流程是严格循环的：

1. 用当前策略 $\pi_{\theta_k}$ 采集一批轨迹；
2. 立刻用这批数据计算梯度、更新参数（通常只更新 1 到几个 epoch）；
3. **把数据扔掉**，回到第 1 步用新策略重新采样。

为什么不能多更新几步？因为参数一变，$\pi_\theta$ 就不再是产生数据的 $\pi_{\text{old}}$，梯度公式里的期望 $\mathbb{E}_{\tau \sim \pi_\theta}$ 就和实际的数据分布对不上了——继续更新等于在"错误分布的估计"上优化，策略可能瞬间崩掉（这也是 2.2 节方差爆炸的另一种表现）。

代价显而易见：**采样极其昂贵**。大模型场景下每一步训练都要让几十亿参数的模型对几万个 prompt 完整生成一遍（rollout），GPU 时间大量花在"生产数据"而非"学习"上。这是 on-policy 方法（PPO/GRPO）工程成本高的根本原因。

### 2.4 PPO：介于两者之间的"近似 on-policy"

PPO 很有意思：它**理论上带了 off-policy 的修正项（概率比 $r_t$），实际上又用 clip 把修正限制在"几乎不需要修正"的范围内**，所以社区习惯称它为 on-policy（更准确说是"近似 on-policy / 轻度 off-policy"）。

回忆 PPO 的目标函数（详见 [3.1.PPO算法详解](3.1.PPO算法详解.md)）：

$$J^{\text{PPO}}(\theta) = \mathbb{E}_{t}\left[\min\big(r_t(\theta) A_t,\ \text{clip}(r_t(\theta), 1-\epsilon, 1+\epsilon)\, A_t\big)\right], \quad r_t(\theta) = \frac{\pi_\theta(a_t\|s_t)}{\pi_{\text{old}}(a_t\|s_t)}$$

- 概率比 $r_t(\theta)$ 本身就是单步重要性采样权重——所以 PPO **允许**同一批数据更新多个 epoch（InstructGPT 中 $K=4$），这是 off-policy 的自由度；
- 但 clip 把 $r_t$ 限制在 $[1-\epsilon, 1+\epsilon]$（如 $[0.8, 1.2]$），保证新旧策略不会差太远——重要性权重的方差被压死在小区间内，也就避免了 off-policy 修正的方差爆炸。

一句话总结：**PPO = on-policy 的稳定性 + 一小口 off-policy 的样本复用，clip 是两全其美的安全带**。GRPO 继承了同样的结构，只是把 critic 换成了组内相对优势（详见 [3.2.PPO到GSPO策略优化算法演进](3.2.PPO到GSPO策略优化算法演进.md)）。

### 2.5 大模型后训练视角：一张分类表

把大模型后训练的主要方法按这对概念归类（on/off-policy 看"数据是谁产生的"，online/offline 看"训练中还能不能产生新数据"，两者独立，见 3.4 节）：

| 方法 | 数据来源 | on/off-policy | 特点 |
|------|----------|---------------|------|
| SFT | 人类写的标准答案 | off-policy（学别人的示范） | 稳定便宜，但没有探索 |
| PPO | 当前模型自己 rollout | on-policy（近似） | 学自己行为的后果，需要奖励模型+价值模型 |
| GRPO | 当前模型组内采样多条回答 | on-policy | 免价值网络，组内相对比较 |
| DPO | 静态偏好对（提前标注） | offline 偏好优化 | 极简稳定，但无法探索、受限于数据分布 |
| RLVR/GRPO+可验证奖励 | 当前模型 rollout + 自动判分 | on-policy | 推理模型（如 DeepSeek-R1）主流路线 |
| On-policy Distillation | 学生在自己 rollout 上对齐教师输出分布 | on-policy（教师只打分不示范） | 2025 年兴起，把强模型能力"蒸馏"进学生自己的轨迹 |

理解这张表的钥匙一句话：**off-policy 意味着模型在学"别人的行为"，on-policy 意味着模型在学"自己行为的后果"**。后训练从 SFT/DPO 走向 RLVR 的演进，本质就是从"学别人"走向"从自己的试错中变强"。

## 3.重要性质

### 3.1 样本效率 vs 稳定性

$$\text{off-policy} \Rightarrow \text{数据可复用} \Rightarrow \text{样本效率高}； \quad \text{on-policy} \Rightarrow \text{数据分布一致} \Rightarrow \text{训练稳定}$$

- off-policy 的数据进经验回放池（replay buffer），一条数据可被学习成千上万次。DQN 里一帧游戏画面会被反复利用，这对"交互昂贵"的场景（机器人、真实用户）至关重要；
- on-policy 每次更新都要求新鲜数据，样本效率低，但**梯度估计无偏且分布一致**，不容易因为陈旧数据把策略带偏。

直觉：off-policy 像"精打细算、旧账翻出来反复研究"，on-policy 像"活在当下、每一步都基于最新的自己"。

### 3.2 分布偏移与修正误差

off-policy 修正有一个隐藏陷阱：重要性采样的方差有下界，当 $\beta$ 与 $\pi_\theta$ 差异大时方差爆炸：

$$\text{Var}\left[\frac{\pi_\theta(a\|s)}{\beta(a\|s)} f(a)\right] \ \text{随两个分布的重叠面积减小而急剧增大}$$

极端情形：$\beta$ 下几乎不产生的动作（比如 $\beta(a\|s)=0.001$），在 $\pi_\theta$ 下很重要——少量这类样本会带上 $1000\times$ 的权重，个别离群样本就能主导整个梯度。实践中的补救：clip 比值（PPO）、限制策略更新步长（TRPO 的信任域）、截断/归一化权重。

直觉：用别人的经验学自己，"别人的经验越不像自己会遇到的情况，折算系数越离谱"。

### 3.3 探索与学习的解耦

off-policy 独有的优势：**行为策略可以随意探索，目标策略可以完全贪心**。Q-learning 用 $\varepsilon$-greedy 的 $\beta$ 采数据，但 TD 目标是：

$$y = r + \gamma \max_{a'} Q_{\bar{\theta}}(s', a')$$

注意 $\max$ 算子本身定义了一个"贪心的目标策略"——目标里**不含行为策略的任何痕迹**，所以数据无论怎么采都不影响"要学成最优策略"这个目标。

on-policy 做不到这一点：它必须让探索发生在自己身上（比如策略里带熵正则、或输出分布本身有温度），探索噪声和学习信号纠缠在一起。

### 3.4 On/Off-policy 与 Online/Offline 是两个独立维度

常见误区是把"on-policy"和"online"混为一谈。实际上它们回答两个不同的问题：

- **Online / Offline**：训练过程中**还能不能拿到新数据/新反馈**？（数据是否持续到来）
- **On / Off-policy**：训练数据**是不是当前策略自己产生的**？（数据由谁产生）

$2 \times 2$ 组合表：

| 组合 | 含义 | 典型例子 |
|------|------|----------|
| Online + On-policy | 持续交互，且只学自己刚产生的新数据 | PPO、GRPO 的标准用法 |
| Online + Off-policy | 持续交互，同时复用回放池里的新旧数据 | DQN、SAC |
| Offline + Off-policy | 只用固定的历史数据集学习 | Offline RL（CQL、BCQ）、SFT |
| Offline + (近似) On-policy | 在静态数据上做策略自身的迭代 | 迭代式/在线化 DPO（如 OPD 变体） |

### 3.5 PPO 的"on-policy"是近似的，DPO 的"off-policy"要分情况说

两个高频精确化表述：

- PPO：概率比 + clip 本质是 off-policy 修正，但 clip 保证 $r_t \approx 1$，即新旧策略几乎相同——所以叫"**近似 on-policy**"。数据能复用 4 个 epoch 左右，再多就因为分布偏移过大而失效（这正是 $r_t$ 被推离 clip 边界的信号）。
- DPO：标准 DPO 在**静态偏好对**上做一次性的监督式优化，既不在线采样、也不做严格的策略迭代，通常称 "**offline 偏好优化**"而非简单贴 off-policy 标签；若把"用当前策略生成回答、再标注偏好"做成循环（iterative/online DPO），它也可以变成 on-policy 流程。

## 4.与其他概念的关系

1. **与重要性采样**：重要性采样是 off-policy 学习的数学基石，off-policy = "on-policy 梯度 × 重要性权重"。PPO 的概率比、GSPO 的序列级比值，都是这个权重的工程化变体。
2. **与 Q-learning/DQN**：off-policy 的经典代表。TD 目标 $r + \gamma \max_{a'} Q(s',a')$ 中 $\max$ 定义了贪心目标策略，与行为策略解耦；replay buffer 打破数据时间相关性，一条数据反复使用。
3. **与 PPO/GRPO**：on-policy（近似）代表。用 clip 的重要性采样换取"同一批数据多次更新"的能力；GRPO 用组内相对优势替代 critic，但 on-policy 采样框架不变。
4. **与 DPO**：DPO 把 RLHF 目标推导成静态偏好对上的分类损失，绕开了在线采样——代价是失去探索能力、效果上限被数据分布锁死。可视为"off-policy 极致"：连环境交互都省了。
5. **与经验回放（Replay Buffer）**：replay buffer 是 off-policy 的标配组件；on-policy 方法不能直接复用 buffer 里的陈旧数据（分布已偏移），这是 PPO 论文明确说明只能用新鲜轨迹的原因。
6. **与模仿学习/SFT**：SFT 是 off-policy 的模仿学习——数据来自人类示范而非模型自身，模型只学"别人怎么做"，不产生"自己做了会怎样"的反馈。
7. **与信任域方法（TRPO）**：TRPO 用 KL 散度约束硬性限制新旧策略距离，本质也是控制分布偏移；PPO 用 clip 近似了同样的目的，但实现成了一阶方法。
8. **与 on-policy distillation（OPD）**：2025 年兴起的思路——教师模型不在自己的示范上教学生，而是在**学生自己的 rollout 轨迹上**给出输出分布监督。数据是学生产生的（on-policy），知识来自教师——试图兼得 on-policy 的分布一致性与蒸馏的效率。

## 5.具体例子

### 例子 1：学打台球——复用数据的价值差

**问题**：一个台球初学者要练"瞄准角度"，on-policy 和 off-policy 两种学法，分别需要多少次击球？

**步骤**：
- on-policy 学法：每次改进瞄准策略后，旧打法下积累的手感全部作废，重新击球收集反馈；
- off-policy 学法：把每次击球（出手角度、力度、进袋结果）都存进"练习日志"，新旧打法的历史日志都能翻出来复盘学习。

**计算**：设策略每改进一版，需要 1000 次击球的数据才能可靠估计"哪种角度进袋率高"。
- on-policy 练 10 版 = $10 \times 1000 = 10000$ 次真实击球；
- off-policy 练 10 版 = 首轮 1000 次击球存入日志，之后每版从 $10^4$ 条日志中反复采样复盘，真实击球仍只需 1000 次左右（数据复用了 10 遍）。

**结果解读**：off-policy 用约 $\frac{1}{10}$ 的真实交互成本达到同样的学习轮数——这就是 replay buffer 的样本效率优势。但注意隐患：日志里前 9 版的旧打法分布与当前策略已经不同（分布偏移），复盘时要靠"这份经验在当前打法下有多相关"来加权——权重算不准，就会拿"过时的手感"指导现在的自己。而 on-policy 虽然贵，但每次复盘的数据都是自己当前打法下的真实手感，学起来最稳。

### 例子 2：PPO 训练中的 clip 如何守住"近似 on-policy"

**问题**：用 PPO 对齐一个语言模型。某条轨迹上，旧策略 $\pi_{\text{old}}$ 生成 token "很" 的概率是 0.25，奖励模型给这条回答打了高分（优势 $A_t = +2$）。训练中同一批数据要过 4 个 epoch，第 4 个 epoch 时该 token 概率被拉高到 0.40，会发生什么？

**步骤**：
1. 计算概率比 $r_t$；
2. 分别算未裁剪项和裁剪项；
3. PPO 取两者中较小的作为目标。

**计算**：
- $r_t = \frac{\pi_{\text{new}}(a_t\|s_t)}{\pi_{\text{old}}(a_t\|s_t)} = \frac{0.40}{0.25} = 1.6$，超出 clip 区间 $[0.8, 1.2]$；
- 未裁剪项：$r_t A_t = 1.6 \times 2 = 3.2$；
- 裁剪项：$\text{clip}(1.6, 0.8, 1.2) \times A_t = 1.2 \times 2 = 2.4$；
- PPO 目标取 $\min(3.2, 2.4) = 2.4$，且由于 $r_t = 1.6 > 1.2$，该项关于 $\theta$ 的**梯度为零**——概率不再被继续推高。

**结果解读**：这个 token 的概率被推到 0.30（即 $r_t = 1.2$）后就"到顶"了。效果是：策略每次相对数据采集策略最多偏移 20%，新旧策略的分布差被钉死在小区间内——**重要性采样的修正始终近似成立**，所以同一批数据复用 4 个 epoch 是安全的。这就是 PPO "近似 on-policy" 中"近似"二字的工程含义：它借用了 off-policy 的复用能力，但用 clip 把偏移量控制到修正几乎不失真的程度。

### 例子 3：DPO 的离线困境——静态数据下的分布偏移

**问题**：同样的偏好对齐任务，改用 DPO（静态偏好对，off-policy 数据）。数据集中"chosen 回答"是人类标注者写的，风格与模型自己的生成分布差别很大。训练 1000 步后会发生什么？

**步骤**：
1. DPO 的损失会同时推高 chosen 的似然、压低 rejected 的似然；
2. 但训练中**模型分布和偏好数据的分布始终不匹配**（chosen 不是模型自己会写出来的）；
3. 随着更新，模型先受益后受损，观察 chosen 概率的变化。

**计算**（典型现象的数字化描述）：设训练初期 chosen 回答在模型下的平均 log 概率为 $-4.0$，DPO 把它推到 $-2.5$（偏好对齐生效）；继续训练到 1000 步后，因为模型被强行拉向"人类风格的分布"，其自身生成质量的评测得分下降，chosen 的 log 概率反而**回落**到 $-3.2$（似然下降现象，DPO 训练中的已知问题）。

**结果解读**：这是 off-policy 数据的根本局限——**模型在学习"别人会怎么回答"，而不是"自己怎么回答会更好"**。静态数据无法反映模型当前的能力边界，训练久了分布偏移累积。对应的 on-policy 解法：让模型自己对每个 prompt 生成 $G$ 个回答（如 GRPO 的 $G=8$），用奖励模型/判分器挑出好坏做组内对比——数据永远是模型当前水平下的输出，不存在"学别人"的偏移。这正是后训练从 DPO 演进到 RLVR/GRPO 路线的核心动机之一。

## 6.常见面试问题

### Q1：一句话解释 on-policy 和 off-policy 的区别？

**答**：区别在于**训练数据由谁产生**。on-policy 要求行为策略（采集数据的策略）和目标策略（正在优化的策略）是同一个，数据由当前策略产生、用完即弃；off-policy 允许两者不同，可以用旧版本策略、专家策略或经验池里的历史数据学习。关键公式：off-policy 需要重要性权重 $\frac{\pi_\theta(a\|s)}{\beta(a\|s)}$ 修正分布差异，on-policy 权重恒为 1。直觉：on-policy 是"自己试错自己学"，off-policy 是"借鉴别人的经验学"。

### Q2：Q-learning 为什么是 off-policy 的？

**答**：看它的 TD 目标 $y = r + \gamma \max_{a'} Q(s', a')$。目标里的 $\max$ 算子定义了一个**完全贪心的目标策略**，而实际采数据用的是 $\varepsilon$-greedy 行为策略——两者天然不同。关键点：TD 目标中**不含行为策略的任何成分**（不像策略梯度需要重新计算 $\pi(a\|s)$），所以无论数据怎么采，都可以拿去更新"要学成最优策略"这个目标。这也是 Q-learning 能配合 replay buffer 的根本原因。

### Q3：off-policy 方法用重要性采样修正分布差异，它在什么条件下会失效？

**答**：单步修正 $\mathbb{E}_\beta\left[\frac{\pi_\theta}{\beta} f\right]$ 理论无偏，但**方差随两个分布的偏离而爆炸**。轨迹级修正尤其严重：权重是整条轨迹上 $\prod_t \frac{\pi_\theta(a_t\|s_t)}{\beta(a_t\|s_t)}$ 的连乘，轨迹长、策略差异大时方差指数增长，个别样本的权重可能上万倍于平均值，梯度被离群样本主导。关键公式：$\text{Var}[\text{权重}]$ 随轨迹长度 $T$ 和 KL$(\pi_\theta \| \beta)$ 增大。直觉：用"几乎不重叠的分布"互相折算，少量样本会带上天价权重。实践中用 clip（PPO）、信任域约束（TRPO）、权重截断来控制。

### Q4：PPO 号称 on-policy，为什么它的目标函数里还有重要性采样（概率比 $r_t$）？

**答**：因为 PPO 想要"同一批数据更新多个 epoch"的 off-policy 自由度（InstructGPT 中 $K=4$），这就必须有 $r_t = \frac{\pi_\theta}{\pi_{\text{old}}}$ 来修正分布差异。关键点在于 clip：$\min(r_t A_t, \text{clip}(r_t, 1-\epsilon, 1+\epsilon) A_t)$ 把 $r_t$ 钉在 $[0.8, 1.2]$ 附近，新旧策略几乎相同，修正误差可忽略。所以准确说法是 PPO 是"**近似 on-policy**"——用 clip 保证策略偏离极小，从而让轻微的 off-policy 修正近似无偏且低方差。

### Q5：DPO 是 on-policy 还是 off-policy？

**答**：标准 DPO 是**离线（offline）偏好优化**：它在提前标注好的静态偏好对上做一次性监督式优化，既不在线采样、也不是严格意义上的策略迭代，简单贴"off-policy"标签容易引起混淆，更准确的说法是 offline。关键点：DPO 的数据来自人类标注而非模型自身（学"别人的偏好"），无法探索模型能力边界之外的行为，效果上限被数据分布锁死。进阶：iterative/online DPO 把"当前策略生成 → 标注偏好 → 再优化"做成循环，就变成了 on-policy 流程；2025 年的 on-policy distillation 思路也是类似的"数据 on-policy 化"。

### Q6：为什么 on-policy 方法不能像 DQN 那样用 replay buffer 反复复用旧数据？

**答**：因为 on-policy 的梯度公式 $\mathbb{E}_{\tau \sim \pi_\theta}[\cdot]$ 要求**数据分布等于当前策略分布**。buffer 里的数据是旧版本策略产生的，策略更新若干步后分布已经偏移，直接复用等于在错误分布上估计期望——梯度有偏且方差可能爆炸（即 Q3 的问题）。关键公式：数据来自 $\pi_{\text{old}}$，而 $\mathbb{E}_{\tau \sim \pi_{\text{new}}}$ 才是想要的目标。直觉：off-policy 方法能复用是因为显式做了修正（或像 Q-learning 那样目标天然与行为策略无关）；on-policy 方法没有修正这个"保险"，只能数据即弃。PPO 是折中：加 clip 做轻量修正，换取同一批数据 2-4 个 epoch 的复用。

### Q7：为什么 LLM 的 RLHF 主流路线（PPO/GRPO/RLVR）都采用 on-policy 采样，而不是用现成人类回答做 off-policy 训练？

**答**：三个原因。① **分布一致性**：RL 要优化"模型自己的输出被奖励模型/判分器打分"，on-policy 数据保证训练分布与部署分布一致，避免 distribution shift 导致的 reward 偏差与 reward hacking；② **探索能力**：模型只有生成自己能力边界附近的输出，才能在试错中变强，静态数据（SFT/DPO）锁死上限；③ **奖励信号的因果性**：on-policy 的优势估计反映"自己这么做会得多少分"，off-policy 数据的优势还要叠加策略差异修正，误差更大。代价是 rollout 成本高（每次更新都要模型重新生成），这也是 LLM RL 训练中生成（rollout）比训练（backward）更耗 GPU 的原因。

### Q8：off-policy 的行为策略可以和目标策略差多远？差太远会怎样，怎么补救？

**答**：理论上没有硬性限制（只要 $\beta(a\|s) > 0$ 覆盖 $\pi_\theta$ 的支撑集，即"行为策略必须尝试目标策略可能选的所有动作"，否则修正无偏性被破坏），实践中差异越大修正方差越大、越容易崩。关键公式：覆盖条件 $\beta(a\|s) = 0 \Rightarrow \pi_\theta(a\|s) = 0$ 必须满足。补救手段：① 限制策略更新步长（TRPO 的 KL 约束、PPO 的 clip）；② 权重截断/归一化（如 DQN 系的优先级回放配重要性权重退火）；③ 增大 $\beta$ 的探索率提高覆盖。直觉：别人的经验可以借鉴，但"别人从来没试过的动作"你永远学不到它好不好。

### Q9：如何理解"on-policy / off-policy"与"online / offline"是两个独立的维度？请各举一个组合的例子。

**答**：Online/Offline 回答"**训练中还能不能产生新数据**"（数据供给方式）；On/Off-policy 回答"**数据是不是当前策略产生的**"（数据归属）。关键区分：Online + Off-policy = DQN/SAC（持续交互 + replay buffer 混合新旧数据）；Offline + Off-policy = Offline RL 和 SFT（纯历史数据集）；Online + On-policy = PPO/GRPO 标准用法。常见误区：把 GRPO 叫"online RL 算法"没错，但不能由"online"推出"能复用历史经验"——它仍是 on-policy 主线，每轮 rollout 只服务于当前一轮更新，不从长期 replay buffer 里随机抽取多代历史数据。

### Q10：（进阶）PPO 的 token 级概率比和 GSPO 的序列级概率比，在 on/off-policy 修正上有什么本质区别？

**答**：PPO 的 $r_t(\theta) = \frac{\pi_\theta(a_t\|s_t)}{\pi_{\text{old}}(a_t\|s_t)}$ 是 **token 级**的比值，每个 token 独立裁剪——修正发生在最小粒度上，但长序列下 token 级误差会累积，且逐 token 比值的连乘方差随长度增长（Q3 问题的 LLM 版）。GSPO（Qwen 团队，2025）改为**序列级**比值 $s_i(\theta) = \left(\frac{\pi_\theta(y_i\|x)}{\pi_{\text{old}}(y_i\|x)}\right)^{\frac{1}{\|y_i\|}}$（对序列长度取几何平均），整条序列一起裁剪——与以序列为单元计算奖励的 LLM 场景天然对齐，训练更稳定。关键点：两者都是"近似 on-policy 框架下控制重要性权重方差"的设计，区别只是把修正与裁剪的粒度从 token 提升到序列。延伸对比详见 [3.2.PPO到GSPO策略优化算法演进](3.2.PPO到GSPO策略优化算法演进.md)。
