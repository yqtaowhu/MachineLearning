# 2025 机器学习场景题精选（系统设计 + 追问拆解）

> 场景题（Scenario / ML System Design）已是 2025-2026 算法岗面试的**重中之重**。据多方真实面经统计：纯八股占比持续下降，面试官越来越倾向"给一个业务场景，让你从零设计方案并扛住连环追问"。
>
> 典型信号：字节/阿里/腾讯大模型与推荐岗的追问已落到"设计支撑十万日活的问答系统""新算法 A/B 输了怎么排查""反欺诈模型被薅羊毛团伙绕过怎么办""检索命中了答案还错问题在哪"——全是**工程现场题**，而非概念背诵题。
>
> 本文档目标：给你一套**万能答题骨架** + 六大高频场景的完整推演 + 面试官追问清单。核心心法是场景题的一句话总纲：**先澄清，再建模；先跑通，再优化；每个选择都讲 trade-off。**

## 一、为什么场景题这样考 + 万能答题框架

### 1.1 面试官在收集哪些信号

场景题没有标准答案，面试官按几个维度打分（Meta/字节面试评估表可参考）：

| 信号维度 | 初级回答 | 加分回答 |
| --- | --- | --- |
| **问题界定** | 上来就报模型名 | 先澄清用户/规模/延迟/成本/成功指标 |
| **建模选择** | "XGBoost 准所以用它" | 说明为何这个指标/损失/约束匹配业务 |
| **数据意识** | 假设数据现成 | 谈标签定义、样本偏差、穿越、冷启动、标注成本 |
| **权衡取舍** | 只讲优点 | 显式讲 latency vs 精度、成本 vs 效果的帕累托 |
| **闭环落地** | 停在训练完成 | 覆盖上线、监控、漂移、回滚、迭代 |

一句话：**能把模糊需求转成清晰的 ML 建模问题、并为每个决策给出理由的人，就是场景题想筛出来的的人。**

### 1.2 万能六步骨架（背下来，任何场景都能套）

$$\text{澄清} \to \text{目标与指标} \to \text{数据} \to \text{建模} \to \text{评估} \to \text{部署与监控}$$

1. **澄清需求（Clarify）**：谁用？在哪个入口用？日活/请求量/QPS 多大？延迟预算多少？错了的代价是什么？——这步防你"解决错的问题"，且几乎每家公司都明确在考。
2. **定义 ML 任务 + 指标（Formulate）**：把业务目标翻译成预测任务（分类/排序/召回/生成），定**离线指标**（AUC/GAUC/Recall@K/nDCG）和**在线北极星指标**（CTR/GMV/留存/人工成本下降），并说明为何选它。
3. **数据（Data）**：标签怎么来、有哪些特征、样本不平衡/选择偏差/特征穿越/冷启动/隐私如何处理。数据是场景题的地基，"数据决定上限"是共识。
4. **建模（Model）**：给一个"能跑通的 baseline"，再演进到 advanced；讲清损失、复杂度、可解释性需求。
5. **评估（Evaluate）**：离线怎么切分（时间切分/留一）、在线怎么 A/B、怎么防离线线上不一致。
6. **部署与监控（Deploy & Monitor）**：架构（召回→粗排→精排 / 双塔→rerank）、缓存、降级、延迟优化、漂移监控、反馈闭环、重训频率。

> **答题节奏**：先用 2-3 分钟把六步的"全景"画给面试官（让他看到完整画面 + 帮你管理时间），再请他挑一步深入。绝大多数追问都会落进下面的模块。

## 二、场景一：冷启动推荐系统

**题目**：一个内容社区 App 刚上线，要做一个"每日推荐"信息流，既没有用户历史行为、也没有物品交互数据，你怎么设计？

### 第 1 步 澄清
- 冷启动分两种，方案完全不同，务必先问清：
  - **用户冷启动**（新用户没行为）；
  - **物品冷启动**（新内容没曝光/交互）——内容社区通常两者都有，且**物品冷启动更痛**（UGC 每秒都在产生新内容）。
- 有无注册信息（性别/年龄/来源渠道）？有无内容本身的文本/图像/标签？日新增内容量级？

### 第 2 步 目标与指标
- 北极星：新用户**次留**、人均消费时长；离线：GAUC（按用户分组算 AUC，避免"活跃用户主导全局 AUC"）、新用户群体的 Recall@K。
- 冷启动期特有指标：**新内容的 24h 曝光覆盖率**（多少比例的新内容能在一天内拿到最低配额曝光）——这是生态健康度指标。

### 第 3 步 数据与特征
- 用户侧：注册画像、设备、来源渠道、地理、**首屏几次点击后的实时行为**（快速热启动）。
- 物品侧：既然没有协同信号，就用**内容特征**——标题/正文过预训练模型出 Embedding、标签、作者历史质量分、封面图特征。这是冷启动的突破口。

### 第 4 步 建模（分层递进）
- **兜底策略**（第 0 天）：热门榜 + 编辑运营规则 + 多样性打散，保证有东西可推。
- **内容召回**：用内容 Embedding 做近邻（用户点过的内容 → 向量 → 找相似新内容），完全不依赖交互，专治物品冷启动。
- **迁移/元学习**：把老场景（如到店）学到的用户偏好迁移到新场景（如外卖），或用 MAML 类元学习让新物品用极少交互快速定位表示。
- **探索机制**：新物品预估方差大 → 用 UCB / Thompson Sampling 给不确定性高的内容加"探索加成"，主动分配曝光收集反馈；配 **Bandcast/EEG 类**探索位。
- **Embedding 冷启动技巧**：新物品 ID 无训练好的向量，用**内容特征初始化** ID Embedding，或用 **Semantic ID（RQ-VAE 编码内容向量成层级码）** 让相似物品共享语义，天然缓解稀疏。

### 第 5 步 评估
- 冷启动不能只看整体 AUC（会被老用户大样本掩盖），必须**分人群/分物品年龄段**看：新注册用户子集、发布 1h 内的新内容子集单独出指标。
- 上线用 A/B：对照组=纯热门，实验组=冷启动模型。

### 第 6 步 部署与闭环
- **曝光保底配额**：新内容保证最低曝光量，避免"没人推→没数据→模型更不敢推"的死循环。
- 反馈实时回流：新用户前几次点击要**低延迟进入模型**（在线学习 / 短期行为序列建模），实现"会话内热启动"。

**追问**：
- "新物品没数据，模型给的分很低，你怎么打破马太效应？" → 探索机制 + 内容相似迁移 + 保底配额三件套。
- "Semantic ID 相比随机 hash ID 的好处？" → 相似物品在语义空间相邻，可共享统计强度、支持泛化到未见 ID，且天然支持生成式推荐。

## 三、场景二：实时交易反欺诈

**题目**：为一个支付平台设计实时交易欺诈检测系统，要求毫秒级决策、极低误伤。

### 第 1-2 步 澄清 + 指标
- 延迟预算？（通常要求 <100ms 同步返回，决定了模型不能太大）。误伤（误拒正常交易）和漏放（放过欺诈）哪个代价更高？一般**误伤直接影响用户和营收**，需在固定拒绝率下最大化召回。
- 指标：在**固定误拒率**（如 1%）约束下看召回；用 KS、按 Recall 固定下的 Precision、以及**每笔期望损失 = 漏放率 × 单笔金额 + 误拒率 × 客单价损失** 做业务化。

### 第 3 步 数据（这是欺诈场景最难的点）
- **极度不平衡**：欺诈往往 <0.1%。应对：负采样 + 概率校准、Focal Loss、类别加权、异常检测（孤立森林/AutoEncoder 重构误差）兜底。
- **标签延迟**：一笔交易是否欺诈要等几天到几周（持卡人争议周期）才确认 → 用 **label delay 建模 / 延迟反馈（delayed feedback）权重**，别用"未确认=正常"污染训练。
- **对抗漂移**：欺诈团伙会快速变换手法，模型一上线就被绕过（"薅羊毛"）。→ 必须设计 **短周期重训 + 规则层热更新 + 图特征**。
- 特征穿越：统计类特征（"该卡近 1h 交易笔数"）只能用**决策时刻可得**的信息，防止用到未来。

### 第 4 步 建模（分层决策）
$$\text{规则引擎（黑名单/硬门槛）} \to \text{无监督（离群/图）} \to \text{有监督模型（GBDT 为主）} \to \text{人审兜底}$$
- 第一层规则：拦截已知模式、保证可解释与合规。
- **图特征**是欺诈场景的杀手锏：设备-卡-商户构成异构图，用 GNN / 标签传播 / 社区发现捕捉"团伙"，单个账户正常但一组账户协同作案。
- 有监督主力仍是 GBDT 系（表格特征、可解释、延迟低、迭代快），深度模型作补充。

### 第 5-6 步 评估 + 部署
- 离线用**时间外推验证**（用过去训、未来测），因为数据强非平稳。
- 线上：决策引擎同步返回、模型异步旁路打分做影子测试（shadow）对比新旧；PSI 监控特征漂移、KS 衰减触发重训。
- 冷启动（呼应经典风控面试）：新品没数据时先"只做规则 + 人审"，或用**同模式产品数据迁移**、**专家评分卡**快速上线，积累贷后表现再迭代出统计模型。

**追问**：
- "模型被团伙绕过、误判率突然升高，怎么排查？" → 先看是**数据漂移**（新特征分布变了：PSI 报警）还是**概念漂移**（好坏定义变了）；拉出漏放样本聚类看是否新欺诈模式；临时上规则热更新止血，再补数据重训。
- "为什么不直接上深度模型？" → 延迟、可解释（监管要求拒贷要给理由）、样本量与迭代速度，GBDT 在表格风控上仍是性价比之王。

## 四、场景三：A/B 实验设计与排查

**题目**：算法团队上线了新推荐算法，A/B 实验里新算法**输给了老算法**，让你找原因，怎么 systematic 地排查？（拼多多/字节真实原题）

这是场景题里出现频率最高的"诊断题"，考的是排查方法论，不是运气。

### 4.1 先质疑实验本身可不可信
1. **样本量够不够 / 显著吗**：算 MDE（最小可检测效应）和功效；两组各 1000 人、100 vs 120 点击这种小样本，差异很可能在噪声内（见[数字例子速览](#数字例子速览)例 1）。用双侧比例 z 检验。
2. **分流有没有污染**：SUTVA 违背——推荐/交易有网络效应（库存、竞价、社交传播），用户间会互相影响，需**时间片轮转 / 聚类随机 / 预算分割**等特殊设计。
3. **有没有新颖效应（novelty effect）**：新交互前期被"尝鲜"抬高或压低，需拉长观察、看留存曲线是否回稳。
4. **AA 检验 / 分桶偏差**：先跑 AA 确认两组基线一致。

### 4.2 实验可信后，按漏斗定位问题环节
电商/内容漏斗：**曝光 → 点击 → 加购/互动 → 转化 → 留存**。逐级对比新老算法各环节转化率，定位掉在哪一层：
- 曝光→点击 掉：推的不对味，查客群画像与推荐内容是否错配（呼应原题答案：从"推送客群"角度归因）；
- 点击→转化 掉：引流品质量差、货不对板，排序目标可能优化了点击却伤了转化（**多目标错配**）；
- 各环节都没明显差、GMV 却降：可能是**长尾/多样性**受损、或头部过度集中。

### 4.3 算法层归因
- **离线好线上差**：查样本选择偏差（离线只用曝光样本，线上要面对未曝光候选）、特征穿越、线上线下特征不一致（TSB）、GAUC vs 全局 AUC（见经典追问）。
- **反馈闭环**：新模型改变了曝光分布，老模型是在旧分布上训的，形成分布漂移；看是否需要联合重训。
- **系统因素**：新模型延迟更高导致超时降级、缓存命中变化、上游召回分布变了。

**答题模板**：先证"实验可信"（样本量/污染/新颖性/AA）→ 沿漏斗逐级定位（哪个转化环节掉）→ 落到"目标错配/数据偏差/延迟降级"三类根因 → 给复现与修复动作。

**追问**：
- "如果新算法只在小流量赢、放大流量就输，为什么？" → 小流量方差大易过拟合噪声；或网络效应/库存约束在大流量暴露；需看是否置信、是否分流单元选错。
- "实验指标涨了但你想叫停，可能为什么？" → 伤害了未纳入的长期/生态指标（留存、供给端、广告负载）、或指标可被"作弊式"短期优化。

## 五、场景四：支撑十万日活的大模型问答系统

**题目**：设计一个日活十万的大模型（LLM）客服/知识问答系统，重点讲稳定性、延迟、成本。

这题 2026 已取代"传统系统设计的增删改查"，成为**大模型版系统设计**必考题。考点是"你能不能把大模型调用当成一个会超时、会烧钱、会幻觉的生产依赖来治理"。

### 5.1 澄清 + 指标
- 是检索增强（有知识库）还是纯生成？峰值 QPS？首 token 延迟（TTFT）与整体延迟（TTLT）预算？单次成本上限？错误答案的品牌风险多大？

### 5.2 分层架构（自顶向下）
$$\text{网关层} \to \text{应用编排层} \to \text{模型服务层} \to \text{检索/工具层} \to \text{可观测与治理}$$

1. **模型网关**：重试、限流、超时、**fallback 降级链**（主模型超时切备用/小模型）、多供应商路由、密钥与配额管理、缓存（语义缓存同问句命中直接返回）。这是"稳定性"的第一道命门。
2. **推理服务层（vLLM/TensorRT-LLM）**：continuous batching、PagedAttention、前缀缓存、投机解码；量化（W8A8/W4A16）降显存提吞吐。
3. **检索/工具层**：RAG 混合检索 + rerank，或 function calling 调业务系统。
4. **Prompt 与上下文管理**：模板版本化、system prompt 缓存复用（前缀 KV cache）、对话历史压缩。
5. **可观测**：全链路 trace、token 级成本归因、幻觉/毒性/拒答率监控、离线评测集 + 在线抽样人工回流。

### 5.3 成本与延迟（面试官最想听"帕累托"）
- **延迟拆解**：TTFT ≈ 排队 + prefill（随输入长度增长）；TPOT ≈ decode 单 token 时间（访存受限）。优化对应：prefill 长 → 前缀缓存/分块；decode 慢 → 投机解码、量化、GQA 降 KV。
- **成本**：并发↑提高 GPU 利用率摊薄单请求成本；用小模型 + 路由（简单问题走小模型，难题升级到大模型）；缓存命中直接省掉整次生成。
- **PD 分离**（prefill/decode 分开部署）是大规模降本增效的前沿点，能提一句是加分项。

### 5.4 安全治理（生产必答题）
输入侧 prompt 注入过滤、输出侧敏感词/PII 脱敏、内容风控；权限继承（知识库 ACL 在检索层生效——最常见的安全事故）。

**追问**：
- "流量突增 5 倍怎么扛？" → 队列 + 限流削峰、按业务优先级分级（VIP 走大模型、普通走小模型/缓存）、水平扩推理副本、超阈值优雅降级到"检索直接返回文档片段"。
- "怎么把平均成本砍一半又不明显掉效果？" → 模型路由 + 语义缓存 + 量化 + 前缀复用四板斧，配合效果回归评测守住底线。

## 六、场景五：RAG 生产系统诊断

**题目**："你的 RAG 系统，检索明明召回了正确片段，但生成的答案还是错的，问题出在哪，怎么排查？"——2025-2026 RAG 面试换味道后的高频原题，考的是"你有没有在真实跑着的 RAG 上调过 bug"。

### 6.1 先分环定位（不要笼统说"效果不好"）
把链路拆成可独立打分的环，用 RAGAS 类指标分别量化：

| 环节 | 指标 | 失败长什么样 |
| --- | --- | --- |
| 检索召回 | Hit-Rate / Context Recall | 正确片段根本没进 top-k |
| 重排质量 | Context Precision | 召回了但排到第 8 位，被截断 |
| 上下文利用 | Faithfulness（忠实度） | 给了正确上下文，答案却与上下文矛盾（本题焦点） |
| 答案相关性 | Answer Relevance | 答非所问 |

**"召回对了但答案错" = 检索环节没问题，锅在生成侧。** 逐项排查：

1. **Lost in the middle**：关键片段在长上下文中部被模型忽略。→ 把最相关证据放首尾（rerank 后重排位置）、减少塞入的片段数（提信噪比，宁缺毋滥）。
2. **上下文冲突/干扰**：召回了多条互相矛盾或相似但错误的片段，模型被带偏。→ rerank 提纯、去重、按来源权威度/时间戳加权，冲突时让模型显式对比或拒答。
3. **Prompt 模板问题**：指令与检索内容混在一起、缺乏"仅依据给定资料作答"的接地约束、few-shot 反而诱导自由发挥。→ 结构化分隔、加强 grounding 指令、要求引用出处（citation）。
4. **切分破坏语义**：chunk 把表格/条件句/定义截断，片段本身残缺。→ 结构感知切分、父-子文档、表格转 Markdown/序列化。
5. **模型能力/温度**：小模型指令跟随弱、温度过高乱编。→ 换更强生成模型、降温度、加"不确定就拒答"。

### 6.2 其他 RAG 现场追问（都会问到）
- "**多证据源冲突信谁？**" → 来源可信度分级 + 时效性加权 + 显式对比 + 冲突检测后拒答/标注分歧。
- "**对话历史太长要压缩，怎么不丢关键需求锚点？**" → 分层摘要 + 抽取式保留用户显式约束（时间/预算/偏好）到独立 slot、而非整段塞进窗口。
- "**知识库怎么更新？**" → 增量索引 + 版本/时间戳 + 失效删除，别让旧文档和新文档同时命中冲突。

**答题心法**：RAG 诊断题要展示"我把它当可观测的多阶段管道来 debug，而不是当黑盒调 prompt"。

## 七、场景六：用户流失预警

**题目**：为一个 SaaS/信贷/电商平台做用户流失预警，识别高流失倾向老客并提前干预。

### 7.1 澄清 + 定义标签（这题最大的坑在"标签定义"）
- 先问"流失"怎么定义——很多公司其实没定义清。常见：**连续 N 天无核心行为**（登录/下单/活跃）算流失，N 取业务周期（toB 常 30/60/90 天）。
- **时间窗设计**：观察窗（用哪段特征）+ 表现窗（未来多久是否流失），中间常留 **gap 缓冲期**，避免把"正在流失"的信号当特征造成泄漏。

### 7.2 特征
行为趋势（登录频次下降、额度使用率骤降、核心功能使用衰减）、交互文本（客服/投诉、情感关键词）、生命周期阶段、历史相似流失客群、竞品替换信号、付费/合同到期时间。

### 7.3 建模两条路线（面试亮点）
1. **分类/概率回归**：给定特征预测"未来 T 天是否流失"概率，GBDT/LR 常用，可解释、易上线。
2. **生存分析（Cox-PH / AFT）**：不止预测"是否"，还预测"**何时**流失"（留存曲线 + 风险评分），能排干预优先级——这是把流失题答深的加分点。

### 7.4 从"预测"到"干预"（区分做过与没做过）
- 预警不是终点，**可干预性**才是：高分用户里要区分"没救了（自然流失）"vs"一挽即回"。理想做法是**增量建模 / uplift（增益模型）**——预测"干预带来的流失概率下降"，把预算花在被干预才有效的人身上，而不是花在本来就会留或必走的人身上。
- 评估：AUC/KS + **按干预 ROI 评估**（挽回 GMV / 券成本）、precision@top-k（运营只处理排名靠前的一批）。
- 闭环：干预实验必须 A/B 验证留存提升，防止"模型把预算撒给了无效人群"。

**追问**：
- "流失是稀有事件、且真实标签要等 90 天才知道，怎么训？" → 延迟反馈建模、用早期代理标签（如 7 天不活跃当弱标签）+ 延迟确认后校正、类加权。
- "为什么不上个大模型？" → 结构化行为表格数据 GBDT 更合适；LLM 可用于**生成挽回话术/策略**（把预测结果 + 交互文本喂给 LLM 生成个性化挽留方案），是"传统模型出分数 + LLM 出行动"的组合。

## 八、追问通用武器库

场景题的分水岭在于扛追问。以下追问在几乎所有 ML 场景题里反复出现，提前备好：

1. **离线指标好、线上效果差** → 样本选择偏差 SSB / 训练服务不一致 TSB / 特征穿越 / GAUC vs AUC / 反馈闭环分布漂移 / 评估集太小在噪声内 / 延迟降级。
2. **类别极度不平衡** → 重采样 / 类加权 / Focal Loss / 换指标（PR-AUC、KS）/ 调阈值按成本曲线 / 异常检测兜底 / 负采样后概率校准。
3. **冷启动（人或物没数据）** → 规则 + 内容特征 / 迁移同构场景 / 探索机制(UCB/Thompson) / Embedding 内容初始化或 Semantic ID / 保底曝光。
4. **概念漂移与对抗** → PSI 监控 + 短周期重训 + 规则热更新 + 在线学习 + 图/时序捕捉异常模式。
5. **延迟/成本受限** → 分层(召回→粗排→精排)、蒸馏/量化/剪枝、缓存、小模型路由、批处理、降级兜底。
6. **可解释与合规** → GBDT+SHAP / 评分卡 / 规则前置 / 拒因可追溯 / 公平性审计（分组指标）。
7. **实验可信性** → 样本量与功效、SUTVA/网络效应、新颖效应、AA 检验、分流单元、长期 vs 短期指标。
8. **"你怎么量化收益"** → 北极星指标 + AB 对照 + 增量（uplift）归因 + 成本核算，形成 ROI 闭环。

> 万能兜底句：**"这取决于业务约束——如果更在意 X，我会选 A 并承受 Y 代价；如果 Y 不可接受，我会退到 B。"** 面试官要的就是这种"带条件的 trade-off"，而非斩钉截铁的唯一答案。

## 数字例子速览

### 例子 1：A/B 实验小样本会不会"假赢"

**问题** → 两组各 1000 人，老算法 100 人点击（10%），新算法 120 人点击（12%），能说新算法更好吗？

**步骤** → 用两比例 z 检验。合并比例 $p = \frac{100+120}{2000} = 0.11$ ，标准误

$$SE = \sqrt{2 p (1-p) / n} = \sqrt{2 \times 0.11 \times 0.89 / 1000} \approx 0.014$$

**计算** → 差异 $0.12 - 0.10 = 0.02$ ，$z = 0.02 / 0.014 \approx 1.43$ ，对应双侧 $p \approx 0.15 \gt 0.05$ 。

**结果解读** → **不显著**，这 2 个百分点完全可能来自抽样噪声，不能据此上线。这正是"新算法看起来赢了其实是噪声"的经典陷阱；要么扩样本、要么延长实验。也解释了为何场景四强调 MDE 与功效计算。

### 例子 2：反欺诈的成本敏感阈值选择

**问题** → 欺诈率 0.1%，模型输出概率。设漏放一笔损失 2000 元、误拒一笔正常交易损失 50 元（客诉+营收），阈值该往哪压？

**步骤** → 最优阈值让"边际多拦一笔的期望收益=0"。当预测概率 $p$ 满足 $p \times 2000 \gt (1-p) \times 50$ 时才值得判欺诈。

**计算** → 临界 $p = \frac{50}{2000 + 50} \approx 0.024$ ，即阈值取 **约 0.024** 而非默认 0.5。

**结果解读** → 欺诈极稀有、漏放代价极高，所以要把判定阈值**大幅压低**（宁可多误伤也不漏），这与"重 Recall"的定性结论完全一致，并用两个业务单价把代价量化了——场景题给出这种带数字的阈值选择，说服力远高于空谈"调整阈值"。
