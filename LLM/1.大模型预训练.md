## 1.概述

**一句话定义**：预训练是在海量无标注文本上，用「预测下一个词」这个简单目标训练一个超大规模 Transformer 的过程——它让模型学会语言规律和世界知识，是一切后继能力（SFT、RLHF、推理）的地基。

**为什么重要**：
- 上游任务越通用，下游迁移能力越强：「预训练 + 微调」范式取代了每个任务从零训练的传统做法。
- Scaling Laws 揭示了性能随参数量、数据量、算力按幂律可预测地提升，这是大模型时代押注「大力出奇迹」的理论依据。

## 2.核心原理

### 2.1 训练目标：Next Token Prediction

GPT 系列采用 decoder-only 架构，目标是自回归地最大化下一个 token 的似然。给定序列 $x_{1:t}=(x_1,x_2,\dots,x_t)$，模型建模条件概率的连乘：

$$p(x) = \prod_{t=1}^{T} p(x_t \mid x_{<t})$$

训练时的损失就是负对数似然（等价于交叉熵）：

$$\mathcal{L}_{\text{LM}} = -\frac{1}{T}\sum_{t=1}^{T} \log p(x_t \mid x_{<t}; \theta)$$

其中：
- $\theta$：模型全部可学习参数；
- $x_{<t}$：位置 $t$ 之前的所有 token（通过 causal mask 保证只看过去）；
- $p(x_t \mid x_{<t};\theta)$：词表上的 softmax 概率分布中第 $x_t$ 个分量。

直觉：这本质上是一个「无限题量的完形填空练习」。每一个位置的下一个词都是免费标签，所以互联网上的所有文本都自动变成了训练数据——这是该范式的数据效率来源。

### 2.2 Tokenizer：BPE 分词

模型不能直接处理字符，需要先分词。主流方案是 **BPE（Byte-Pair Encoding）或其变体（Byte-Level BPE / SentencePiece）**：

1. 初始词表为所有单字节（256 个基础符号）；
2. 统计语料中相邻符号对的共现频率；
3. 把最高频的一对合并成一个新 token，加入词表；
4. 重复步骤 2-3 直到达到目标词表大小（常见 3 万 ~ 25 万）。

例如词表扩张过程可能是：`l o w` → 合并 `lo` → 合并 `low`。这样高频词最终成为单个 token，稀有词退化为字节序列，保证任何输入都能被编码（无 OOV）。

### 2.3 数据工程流水线

工业界预训练数据典型处理链路（以 LLaMA 类项目为例，原始语料数 PB 级 → 最终 1~15T token）：

```
网页爬取（Common Crawl）
   ↓ 去重（URL / MinHash + LSH 近似去重）
   ↓ 语言过滤（fastText 分类器筛英文/中文）
   ↓ 质量过滤（启发式规则 + 打分模型筛选）
   ↓ 有害内容过滤（nsfw、暴力、隐私信息如邮箱/IP）
   ↓ 混合配比（web : code : 书籍 : 论文 按权重采样）
   ↓ 多轮 Epoch 或退火（高质量数据放到训练末期）
```

关键经验：
- **代码与数学数据**不仅提升编程能力，还能显著提升推理能力；
- **数据配比**比总量更关键：同一 token 预算下，好的 mixture 可以带来数个点的 benchmark 提升；
- **Cosmopedia/ FineWeb-Edu 式合成与过滤**：用小模型给网页打教育价值分，只在高分语料上训练，能用更少 token 达到更好效果。

### 2.4 Scaling Laws（缩放定律）

OpenAI（Kaplan et al., 2020）发现测试损失与参数量 $N$、数据量 $D$、训练算力 $C$ 满足平滑幂律：

$$L(N, D) = E + \frac{A}{N^{\alpha}} + \frac{B}{D^{\beta}}$$

拟合值大致为 $A\approx 406.4,\ B\approx 410.7,\ E\approx 1.69,\ \alpha\approx 0.34,\ \beta\approx 0.28$（对自然对数尺度的实验）。三段中的主导项决定了瓶颈在哪里：参数太小补多少数据都没用，反之亦然。

**Chinchilla 修正**（Hoffmann et al., 2022）：在算力最优（即给定 FLOPs 下最小化 loss）时，参数量和数据量应当**同比例增长**，经验法则是：

$$D_{\text{optimal}} \approx 20 \times N \quad (\text{约每 } 1 \text{ 参数配 } 20 \text{ 个训练 token})$$

即一个 70B 模型约需 1.4T token 才「吃满」，之前 GPT-3（175B 只训 300B token）是明显欠训练的。

**过训练趋势**：推理成本 dominates 服务开销，因此现代开源模型普遍选择 smaller model + more data（如 Llama 3 8B 用了 15T token，远超 Chinchilla 最优），用训练成本换推理成本。

### 2.5 长上下文与并行策略（简述）

- **位置编码外推**：RoPE 底数放大（如 base 从 10000 → 500000）、NTK-aware 缩放、YaRN，实现短训长推；
- **分布式训练**：数据并行 DP、张量并行 TP（矩阵切块切到多卡）、流水线并行 PP（层间切分）、ZeRO/FSDP（优化器状态、梯度、参数分片），组合使用支撑千亿级训练。

## 3.重要性质

**性质 1：预训练目标与下游应用天然同构**
公式：训练时 $p(x_t|x_{<t})$，推理时正是逐 token 生成的分布。这意味着预训练分布和生成式应用零 mismatch，而 BERT 的 MLM 在此处有 train-test 不一致的问题。

**性质 2：Cross-entropy loss 对困惑度的指数放大**
困惑度 $\text{PPL} = \exp(\mathcal{L})$。例：loss 从 2.30 降到 2.00，PPL 从 9.97 降到 7.39——看似 loss 只降了 0.3，实际错误分支的平均数量砍掉约 26%。这就是为什么「loss 小数点后的第二位」在预训练监控中也值得关心。

**性质 3：幂律意味着边际收益递减**
由 $L \sim N^{-0.34}$：把参数量扩大 10 倍（×10），loss 下降因子为 $10^{-0.34}\approx 0.457$，即约下降一半多一点；再扩大 10 倍又只能降一半。所以性能提升「永远有效」但「越来越贵」。

**性质 4：涌现能力与度量方式有关**
在精确匹配类任务（多步推理、拼字）上，小模型近乎随机、大模型跳跃式提升，表现为「涌现」；但换成连续度量的指标（如 multi-token accuracy）曲线往往又是平滑的。是否真涌现仍有争论，但实践中模型规模跨过阈值后 abilities 变化确实剧烈。

**性质 5：Loss 尖峰（loss spike）常见且需预案**
训练中途因数据坏 batch、混合精度数值问题出现 loss 跳升是常态，工业界常用回滚 + 跳过可疑数据段的方式恢复，而不是从头重训。

## 4.与其他概念的关系

| 维度 | 预训练 | SFT | RLHF |
|---|---|---|---|
| 数据 | 海量无标注文本（TB 级） | 几万~百万条指令-回答对（人工/AI 生成） | 人类偏好对比数据 + 模型自己rollout |
| 目标 | 模仿下一 token 分布 | 模仿示范答案的条件分布 | 最大化奖励、对齐人类偏好 |
| 成本 | 占总算力 95% 以上 | 极低（几百 GPU·天量级） | 中等（RM 训练 + 强化学习循环） |
| 改变什么 | 注入知识与语言能力 | 学会对话格式、遵循指令 | 行为风格、有用性/无害性打磨 |

类比：预训练像「读完全部课本」，SFT 像「刷几年真题学答题规范」，RLHF 像「请家教针对你的答题风格反复点评修正」。

与经典自监督方法对比：
- **BERT（MLM）**：双向编码器，只会「完形填空」，不善生成 → 适合判别任务；
- **T5（span corruption）**：encoder-decoder，统一成 text-to-text；
- **GPT（causal LM）**：decoder-only，生成与推理规模化最顺，成为当代主流。

## 5.具体例子

### 例子 1：手算一个迷你 next-token prediction 损失

**问题**：词表只有 5 个词 $\{$猫， 坐， 在， 垫子， 上$\}$，训练句子「猫 坐 在 垫子 上」。某时刻模型输出分布不理想时，交叉熵如何体现「惩罚」？

**步骤与计算**：
假设到了最后一个位置，真实下一词是「上」，模型给出的概率分布为：

$$p(\cdot|\text{猫 坐 在 垫子}) = [\text{猫}:0.01,\ \text{坐}:0.02,\ \text{在}:0.05,\ \text{垫子}:0.12,\ \text{上}:0.80]$$

单步交叉熵损失：

$$\ell = -\log 0.80 = 0.223$$

如果模型很差，「上」的概率只有 0.04：

$$\ell' = -\log 0.04 = 3.219$$

**结果解读**：概率每缩小 10 倍，损失就增加 $\ln 10 \approx 2.303$。把整句 5 个位置的平均损失降到接近 0，等价于模型在每个位置都能把极大概率压在真实的下一个词上——整个预训练就是在全互联网规模上重复这件事数十亿次。

### 例子 2：用 Chinchilla 法则估算训练配置

**问题**：团队有算力预算可以训练一个 8B 参数的稠密模型，按 Chinchilla 最优应该配多少数据？若改为「过度训练」路线（对标 Llama 3 8B），需要多少？

**步骤与计算**：
- Chinchilla 最优：$D = 20N = 20 \times 8\times 10^9 = 160\times10^9 = 1.6\times 10^{11}$，即 **1.6T**？不对，注意单位换算：$20 \times 8 = 160$ 个十亿 token，即 **160B token ≈ 0.16T**。
- 过度训练路线：Llama 3 8B 实际用了 **15T token**，约为 Chinchilla 最优的 $\frac{15000}{160} \approx 94$ 倍。

**结果解读**：两者相差近百倍！原因在于部署侧：8B 模型要服务海量请求，多做 90 余倍的计算把它练到极限，可以在推理端长期省下巨大开销；同时对开源社区而言，一个更强的小模型比一个没吃饱的大模型更有价值。这也解释了近两年「small model, heavy training」的行业趋势。

### 例子 3：BPE 如何压缩长文本（影响成本的直觉）

**问题**：「unbelievable」在不同词表下的 token 数和 API 成本有何差别？

**步骤**：
- 词表只有单词级别不含该词时（byte-level 回退）：`u n b e l i e v a b l e` → 约 11 个 token；
- 中等规模词表（32k）：`un believ able` → 3 个 token；
- 大词表（128k，含常用词素）：`unbeliev able` 或整词 → 1~2 个 token。

**结果解读**：token 数直接决定按 token 计费的成本和上下文窗口能装下的内容量。中文场景尤其明显：早期 32k 词表一个汉字常拆成 2~3 个 token，如今主流大词表已做到大部分汉字 1 token，这也是「国产模型 API 相对便宜」的技术因素之一。

## 6.常见面试问题

### Q1：为什么现在的主流大模型几乎都用 decoder-only 架构？
**答**：(1) 训练目标与生成任务同构，无 pretrain-finetune 使用不一致；(2) causal mask 使每个位置都提供监督信号，sample 效率高（BERT 的 MLM 每个 sample 只 mask 一小部分）；(3) 结构简单便于 scaling 和 KV Cache 优化；(4) 实证上同等算力下 decoder-only 效果更好（zero-shot 迁移强）。

### Q2：写出 GPT 预训练的目标函数，并解释与 perplexity 的关系。
**答**：$\mathcal{L}=-\sum_{t}\log p_\theta(x_t|x_{<t})$（取平均）。困惑度 $\text{PPL}=\exp(\overline{\mathcal{L}})$，可解释为「模型在每个位置平均犹豫的选择数」。PPL=100 时相当于每一步模型认为约有 100 个词同样合理。

### Q3：Scaling Laws 中 Chinchilla 论文的核心结论是什么？它与 OpenAI Kaplan 版本有什么差异？
**答**：Kaplan 认为应优先扩参数；Chinchilla 用更大规模的实验（400+ 模型）发现在固定算力下参数量与数据量应**等比例增长**（约 1 参数 : 20 token）。用同样算力把 Gopher 280B 缩到 70B 并加 4 倍数据，全面超越原模型。差异根源包括拟合函数形式、学习率调度设置与实验覆盖范围。

### Q4：为什么预训练后还要做 SFT，而不是继续加大预训练？
**答**：预训练数据是「文档续写」分布，与应用时「指令→回答」分布不匹配；不加 SFT 模型可能只会接着用户的问题续写而不是回答。SFT 以极低成本完成行为格式转换，投入产出比远高于继续堆预训练 token。

### Q5：MinHash + LSH 去重的原理是什么？为什么要做文档级去重？
**答**：把文档切成 shingles（n-gram 集合），用多个哈希函数生成 MinHash 签名近似估计 Jaccard 相似度；LSH 分桶把签名分成 band 加速近邻查找。重复数据的危害：(1) 浪费算力；(2) 高频重复导致记忆化（逐字复述背诵内容）甚至污染评测集；(3) 放大数据偏差。

### Q6：RoPE 是什么？为什么长上下文扩展常围绕它做文章？
**答**：Rotary Position Embedding 把位置信息以旋转变换作用在 Q/K 上：注意力内积只依赖两个位置的**相对距离**，且可写成绝对位置编码的形式（无需改动 attention 结构，天然兼容 KV Cache）。长上下文外扩时改 RoPE 底数/插值（Position Interpolation、NTK、YaRN），可以让仅见 4k 数据的模型外推到 128k，因为高频维度对应近距离、低频维度对应远距离关系。

### Q7：数据混合（data mixing）为什么重要？知识一点的「退火阶段」是什么操作？
**答**：不同来源数据的学习难度和价值不同，混合比例直接决定各领域能力的均衡；实验发现 web 数据占比过高会稀释数学/代码收益。「退火」（annealing）指训练末期切换到高质量数据子集并降低学习率，让模型最后吸收最有价值的样本，loss 曲线会额外下降一段。

### Q8：训练 loss 出现尖峰（spike）应如何排查和处理？
**答**：排查顺序：(1) 定位发生时间附近的 data shard，检查脏数据；(2) 检查数值稳定性相关组件（混合精度、gradient clipping 是否失效）；(3) 观察 spike 是否伴随梯度范数异常。处理：从上一个 checkpoint 回滚、跳过可疑数据段重启，必要时下调学习率；避免盲目全量重训。

### Q9（进阶）：什么是 Muon/深层网络 optimizer 的新趋势？它们与 AdamW 的区别？
**答**：新方向是利用参数矩阵的二阶几何信息（正交化更新，如 Muon 对 momentum 更新做 Newton-Schulz 正交化），在 Transformer 的隐层矩阵上展现了更好的样本效率，已在 NanoGPT speedrun 等实验和部分工业训练中被验证可比 AdamW 更快收敛；embedding/head 层仍保留 AdamW。考察点在于理解 AdamW 的自适应逐元素缩放忽视了矩阵的整体谱结构。

### Q10（进阶）：解释「预训练-中等训练-post-training」三阶段的 token 预算分配思路。
**答**：粗略经验：预训练占绝大部分算力（>95%）；mid-training 可包含 continued pretraining、选择题式 QA 化（如 FLAN 风格大规模多样任务）；post-training（SFT+RLHF/RLVR）数据量小但决定可用性。预算的本质权衡是：知识容量主要由预训练决定，行为和能力激发由 post-train 决定，后者便宜得多，因此行业趋势是 post-train 数据质量上限不断抬高（高质量的几十万条可媲美百万条平庸数据）。
